# 第一卷《黑雨》内容包接入说明

## 交付边界

本内容包当前包含 365 个可执行 StoryNode，是第一卷《黑雨》的**完整可接入内容包**；全节点可读小说母稿为 110,295 汉字。现有内容覆盖三座中型副本、村庄与人物回访、材料显形、十二个微型遭遇、北滩谈判、四条主结局及其后日回访，并新增黑雨七日记、六件普通事、未送达回执、雨后初课等可回访叙事组，均以节点、任务、遭遇、材料/图鉴或世界状态接入；章节结构、区域与验收口径见 `10小时章节扩展蓝图.md`。它服从 V1.3 母文档的核心约束：普通人视角、知识驱动、多解遭遇、材料显形、山海志分层、选择余响、稳定 ID 和显式 Effect。游玩时长仍需以新档实测确认，不以节点数或全文字数替代试玩结论。

主线单周目的文本路径约为全部节点的一个子集；完整阅读稿收录所有互斥路线，供策划审稿，不代表玩家一次流程会依次看见全部内容。

## 文件职责

- `story-nodes.json`：五幕主线正文、对话、条件余响、选项、条件、代价与状态效果。
- `story-nodes-expansion.json`：副本深化、人物/地点回访、材料显形、谈判与结局后日内容；运行时与构建器会与基础节点合并加载。拆分文件仅为降低审稿与合并冲突，不是脱离接口的正文副本。
- `characters.json`：11 名主要角色的人格、动机、秘密、口吻、关系轴与跨卷钩子。
- `player-origins.json`：8 种出身的开场插值、初始知识、物件与关系种子。
- `items.json`：28 件本卷物品/材料/证据，含感官文本、认知阶段、效果、代价与剧情引用。
- `quests.json`：5 条主线与 26 条支线；目标使用状态条件判断，不依赖 UI 点击计数。
- `encounters.json`：含晦与水客精英遭遇及 10 个知识/资源型微遭遇；均提供替代解决路径与继续叙事的失败代价。
- `codex.json`：32 个山海志条目，以初见、众口、行证、洞彻/余响分层。
- `world-state.json`：默认世界状态、枚举和第二卷输入绑定。
- `黑雨_完整游戏小说.md`：由构建脚本生成的全节点可阅读母稿。
- `黑雨_文学扩写版.md`：核心场景的小说化扩写，供审稿、配音、美术氛围与演出拆解；不替代运行时节点数据。
- `文本结构研究与应用.md`：本轮场景结构、对话与人物塑造的公开资料研究摘要和可复用写作模板。
- `10小时章节扩展蓝图.md`：从垂直切片扩展至完整探索约10—12小时的内容量、区域、副本、人物线与验收基线。

## 运行时接口映射

| 游戏接口 | 数据入口 | 关键字段 |
| --- | --- | --- |
| 剧情引擎 | `story-nodes.json` + `story-nodes-expansion.json` | `blocks`, `choices`, `next`, `onEnterEffects`, `onExitEffects` |
| 条件/分支 | 所有内容文件 | `visibleWhen`, `enabledWhen`, `unlockRules`, `completion` |
| 命令总线 | 剧情与任务 Effect | `type` 加参数；UI 不直接改状态 |
| 任务系统 | `quests.json` | `objectives`, `optionalObjectives`, `rewards`, `failure` |
| 背包/材料 | `items.json` | `recognitionStages`, `properties`, `recipes`, `hazards` |
| NPC/关系 | `characters.json` | `relationshipAxes`, `state`, `arcStage`, `knowledge` |
| 战斗/遭遇 | `encounters.json` | `intentModel`, `solutions`, `failureResults`, `worldEffects` |
| 山海志 | `codex.json` | `layers[].unlockRules`, `sourceVoice`, `reliability`, `contradictions` |
| 存档/跨卷 | `world-state.json` | `defaults`, `echoBindings` |
| 角色创建 | `player-origins.json` | `originScene`, `statBonuses`, `startingItems`, `choiceTags` |

TypeScript 最小契约在 `src/content/contracts.ts`，可运行适配示例在 `src/content/blackRainAdapter.ts`。适配器只读取状态并派发显式命令，未把 UI、存储或随机实现绑进内容。

## 推荐加载顺序

1. 读取 `manifest.json`，核对 `schemaVersion` 与 `contentVersion`。
2. 并行加载 manifest 中列出的 JSON；用稳定 ID 建立只读索引。
3. 以 `world-state.json/defaults` 初始化新档，再应用出身种子。
4. 从 `entryNodeId` 进入剧情；节点进入/退出和选项只向 `CommandBus` 派发 Effect。
5. UI 使用 `GameStateReader` 过滤条件块、可见选项和锁定状态。
6. 物品名称与说明必须按认知层读取，实体 ID 永不因显形而改变。
7. 每个 Effect 记录来源节点/选项、内容版本、随机种子及状态前后摘要。

## 状态与内容约定

- ID 发布后不改。显示名称、正文修辞可以版本化调整。
- `setFlag` 只用于真正二元线索；阶段、归属、数量均使用 `setWorldVar`。
- `conditional` 正文块用于卷末余响等动态小说段落，不在内容生产阶段复制四份结局正文。
- `sourceTag` 是 UI 展示标签，不直接等于判定条件；实际门槛仍由 `visibleWhen/enabledWhen` 决定。
- `costs` 必须先校验再执行；不可逆选项由 UI 二次确认。
- `failureResults` 都是继续叙事的代价路线，不用普通主线 Game Over 截断内容。

## 构建与校验

使用工作区提供的 Python 运行：

```powershell
python tools/build_black_rain.py
```

脚本会校验 JSON 解析、全局/选项 ID 唯一性、节点可达性、节点跳转、NPC/物品/任务/遭遇/山海志引用和 manifest 数量，并重新生成可阅读小说稿。通用初始物品使用 `IT-GENERIC-*` 外部命名空间，不属于本卷内容包。

## 尚需人类冻结的三项内容决策

1. 三影者的本体在第二卷是否给出唯一答案；当前设计刻意保留“人格/道路/残日”三者并存。
2. 羿、十日、扶桑相关内容的原典与演化标签需由文化审校文档补充具体出处版本。
3. 内容规模已达到本轮 11 万汉字、365 节点的生产目标；完整版本仍以“首通 3—4 小时、全探索 10—12 小时”为验收目标，必须由新档试玩记录、分支覆盖和阅读节奏复盘确认，不能用配音、停顿、节点数或刷取时长替代。
