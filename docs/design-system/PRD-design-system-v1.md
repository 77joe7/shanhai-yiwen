# 设计系统 v1 · 产品需求文档（PRD）

> 项目：《山海异闻录：天地未定》第一卷《黑雨》
> 文档性质：简单 PRD（含设计系统本体 + 可交互 living demo），无竞品分析、无市场调研
> 基线依据：说明书 V1.3（三/十一/十二/十三章）+ `tmp/stitch-ref/DESIGN.md` 机器可读令牌
> 作者：许清楚（产品经理）｜日期：2025-08-19

---

## 一、产品目标

构建一套以《山海异闻录》现有 UI 规范（暗色「湿墨石」古卷）为唯一真源的设计系统：将规范中的色彩、字体、间距、形状/层次、纹理动效令牌化为统一、可机读的令牌层，并据此实现 12 个核心组件的样式与状态契约及交互/可访问性规范；同时优先交付一个网页端可交互的实时演示（living demo），让设计师、前端与主理人能直观验证令牌取值、组件行为与交互规范的一致性，便于在不开发完整游戏产品的前提下快速迭代与评审。

---

## 二、用户故事

1. **设计师（验证令牌）**：作为 UI 设计师，我希望在 demo 中看到全部色彩/字阶/间距令牌的真实渲染与取值，并能一键复制 CSS 变量或色值，以便在不同工具间保持一致、避免凭记忆取色。
2. **前端（查组件用法）**：作为前端工程师，我希望在 demo 中按说明书十一查看 12 个组件的属性、状态与样式契约及用法说明（何时用、反例），以便按统一契约实现，不各自发明样式。
3. **主理人（评审一致性）**：作为主理人，我希望 demo 能切换高对比/减弱动效、模拟三档断点，并对偏离规范的值给出差异高亮，以便快速评审设计系统是否"完整且一致"。
4. **可访问性校验者**：作为可访问性负责人，我希望 demo 真实展示 44×44 触控区、键盘焦点环、读屏语义标签与高对比结果，以便验收是否满足 WCAG 2.2 AA。
5. **微信小游戏迁移负责人**：作为后续迁移负责人，我希望令牌与组件不耦合具体平台 API，以便同一套设计语言平滑迁移到微信小游戏运行时。

## 三、色彩基调决策（前置定调，架构与实现的前提）

### 结论

**设计系统 v1 以规范暗色「湿墨石」基线为唯一真源（单一主题），不实现浅色纸卷双主题。**

### 理由

1. **规范权威性**：说明书三/十三章与 `DESIGN.md` 是经批准的受控文档，且主理人将其定为"权威基线"。`globals.css` 当前的浅色纸卷（`--paper:#e8e5d9`、`--ink:#171b18`、`.game-shell` 浅色渐变）是**偏离基线的实现态**，说明书中并无任何浅色纸卷令牌支撑。
2. **需求符合度**：用户要求"基于现有的 UI 规范"构建"完整且一致"的系统；"一致"的前提是单一真源。双主题会引入两套令牌与组件适配、制造漂移，且明显扩大范围（违背"不扩大范围、简洁优先"）。
3. **可访问性定位**：暗色古卷是高对比、低噪声的叙事基线；说明书十二明确高对比与减弱动效是"模式开关"而非"第二主题"。
4. **平台一致**：微信小游戏迁移（说明书十三.5）沿用同一暗色信息层级，单一主题降低两端实现偏差。

### 影响面

- **令牌层（本 PRD 范围）**：仅定义规范化**暗色**令牌集（说明书三.1 + 黑雨补充语义色），不定义浅色令牌。
- **`globals.css` 遗留不一致（需架构师处理的技术债，非新增功能）**：
  - 浅色默认变量 `--paper/#e8e5d9`、`--ink/#171b18` 及 `.game-shell` 浅色渐变（约 L4–L28、L410）；
  - 偏绿暗色覆写 `html[data-theme="dark"]`（#161b17/#1b201b/#242a20，约 L213–L217）与近似暗色的 `.mythic-shell`（L550）——均偏离规范暖墨/焦金取值；
  - **287 处硬编码色值**（绕开 CSS 变量，如 `#3e463f`、`#9d4a3b`、`#b5ad9d`、`#d15a42`、`#c4a46a` 等）需在集成阶段统一替换为规范令牌引用。
  - 上述改造属"设计系统集成"工作，v1 优先落地 living demo；对 `globals.css` 仅做**遗留不一致标注**，具体改造由集成任务（任务 #3）评估工作量并单独评审。
- **游戏默认观感回归**：若设计系统后续集成到 `app`，游戏外观将从浅色纸卷切回暗色湿墨——这是符合规范的正向回归，但涉及 200+ 硬编码值改造，须作为独立评审项。
- **living demo**：默认且只渲染暗色；高对比开关在暗色内切换（提对比/降纹理），**不切换浅色**。

## 四、需求池（P0 / P1 / P2）

> 验收标准均须可测量、可演示。P0 覆盖用户点名的五大要素：色彩、字体、间距、组件样式、交互规范。

### P0（Must have）

- **P0-1 色彩令牌体系**：从说明书三.1 提取并规范化全套暗色色彩令牌，含 表面/容器层级（background→surface-container-highest）、文字（on-surface/on-surface-variant）、边框（outline/outline-variant）、主要交互（primary/primary-container）、焦金（tertiary-container/primary-fixed-dim）、朱砂（secondary-container）、错误（error/error-container），以及黑雨补充语义色（生息=朱砂/暗红、精力=焦金/暗赭、定力=低饱和冷月蓝、自然=低饱和苔绿）。以 **CSS 自定义属性 + TS 常量双形态**交付，值必须来自规范、可被 demo 读取与复制。
  - 验收：令牌覆盖规范全部色值；无新增硬编码；提供 `--xxx` 与 TS 常量两种引用；语义色均附文字（不唯色）。
- **P0-2 字体令牌与字阶**：按规范定义 **6 级字阶**（显示标题 36/700/1.2/0.1em、大标题 24/600/1.4、手机标题 20/600/1.4、叙事正文 18/400/1.8、辅助正文 14/400/1.6、标签 12/700/1/0.2em），含中文回退栈（Noto Serif SC / Literata 或高可读中文宋体 / Source Serif 4），并定义字体加载与失败降级策略（不低于系统衬线回退）。
  - 验收：6 级均可于 demo 字阶尺渲染；移动窄屏正文逻辑≥16px（规范下限）；字体缺失时回退不破版。
- **P0-3 间距令牌与间距尺**：以 4px 为基，定义 **6 档间距**（unit 4 / stack-sm 8 / gutter 12 / stack-md 16 / margin-edge 20 / stack-lg 24），以 `--space-*` 交付，并与 Tailwind 4 theme 映射一致。
  - 验收：6 档齐全且可在 demo 间距尺按真实像素可视化；叙事段落间≥24px。
- **P0-4 形状/边框/层次 & 纹理动效令牌**：圆角=0（兼容最大≤4px）、1px 细金边 30%/60% 两态、刷痕分隔线（两端透明、中部淡金渐变）、5% 噪点纹理层（pointer-events:none、不降对比）、减弱动效降级规则（关闭脉冲/过渡/视差/逐字，保留即时状态）。
  - 验收：组件库统一使用 shape/elevation 令牌；无厚阴影；噪点层不阻塞交互。
- **P0-5 12 组件样式契约**：按说明书十一逐一实现 12 组件属性/状态/样式契约——AppTopBar、BrushDivider、NarrativeBlock、ArchiveEvidenceCard、SquareTag、StatusMeter、ThreatPanel、ActionButton、MapMarker、LocationCard、CharacterQuestDrawer、BackToLatestButton。统一直角细边、方括号标签（非 pill）、状态变化不唯色。
  - 验收：12 组件在 demo 陈列且各状态可触发；与说明书十一契约一致（含 ArchiveEvidenceCard 7 状态、ThreatPanel 6 状态、ActionButton 翻转填充等）。
- **P0-6 交互与可访问性规范落地**：触摸最小 44×44、相邻≥8px；键盘 Tab 顺序=视觉顺序、2px 焦点环+3px 偏移；语义区域标签；高对比满足 WCAG 2.2 AA；减弱动效；错误（朱砂边线+文字+可恢复）与空状态（淡金符号+简短说明）规范。
  - 验收：demo 可切换高对比/减弱动效并即时反映；焦点环可见；关键状态有文字/图标/结构三重表达。
- **P0-7 可交互 living demo 网页**：独立网页实时演示，含令牌画板、字阶尺、间距尺、12 组件陈列、交互/状态切换器、响应式断点模拟；支持高对比开关、减弱动效开关、令牌值一键复制。
  - 验收：所有控件真实改变渲染（非静态截图）；可本地 dev server 运行；覆盖 P0-1~P0-6 全部要素。

### P1（Should have）

- **P1-1 令牌文档化 UX**：demo 内令牌可搜索、按组（色彩/字体/间距/形状）筛选，点击复制 `--var` 或色值。
- **P1-2 组件用法文档**：每组件含 props/状态/何时用/反例，供前端查用法。
- **P1-3 断点模拟器**：实时切换手机 360–720 / 平板 721–1050 / 桌面 >1050 并标注当前断点。
- **P1-4 令牌↔Tailwind 4 双向映射**：CSS 变量驱动 Tailwind token，便于一致性评审。
- **P1-5 一致性自检**：demo 对偏离规范值的渲染做差异高亮（如某色偏离规范即标红），供主理人评审。

### P2（Nice to have）

- **P2-1 浅色纸卷双主题骨架**：**仅当用户后续确认产品需要浅色时**才做；v1 不实现（见第三节决策）。
- **P2-2 组件组合示例**：NarrativeBlock + BrushDivider + SquareTag 组合成真实剧情片段，展示契约协同。
- **P2-3 令牌导出**：支持导出 JSON / CSS / TS 多格式下载。
- **P2-4 动效对比**：减弱动效下组件行为录制/对比。

## 五、living demo 页面需求

### 5.1 展示区（Display Zones）

1. **令牌画板（Token Swatches）**：色彩令牌色块网格——容器层级梯度、文字/边框、主要交互、焦金、朱砂、错误及黑雨补充语义色；每块显示名称+`--var`+HEX+对比度比值。
2. **字阶尺（Type Ruler）**：6 级字阶真实渲染，标注字号/字重/行高/字距与中文回退。
3. **间距尺（Spacing Ruler）**：6 档间距以真实像素条可视化，标注 4/8/12/16/20/24。
4. **12 组件陈列（Component Gallery）**：按说明书十一逐一陈列 12 组件，每个展示其全部状态（如 NarrativeBlock 旁白/NPC/玩家/异兆/逐字态；ArchiveEvidenceCard 未知→洞彻；StatusMeter 不同填充与 warning；ThreatPanel 危险等级；ActionButton 启用/禁用/危险/翻转）。
5. **交互与状态切换器（Interaction & State Playground）**：逐字动画演示、焦点环演示、读屏语义标注、高对比/减弱动效效果对比、组件状态联动切换。
6. **可访问性演示（A11y Showcase）**：44×44 触控区描边、键盘 Tab 顺序与焦点环、语义区域轮廓、高对比模式结果。
7. **响应式断点模拟（Breakpoint Simulator）**：外框视口宽度滑块/预设，套用三断点并标注当前档位，验证主内容列不无限拉伸、导航模型一致。

### 5.2 可交互控件（Interactive Controls）

| 控件 | 作用 | 真实性要求 |
|---|---|---|
| 高对比开关 | 切换暗色内高对比令牌（提对比/降纹理） | 即时改变全局令牌，满足 WCAG AA |
| 减弱动效开关 | 关闭脉冲/过渡/逐字，保留即时态 | 即时生效，NarrativeBlock 转全文直显 |
| 断点模拟（宽度滑块/预设） | 手机/平板/桌面三档 | 实时重排，标注当前断点 |
| 组件状态切换器 | 每组件切换其已定义状态 | 真实改变组件渲染，非截图 |
| 令牌值一键复制 | 复制 `--var` 或 HEX | 写入剪贴板并反馈 |
| 逐字动画演示开关 | NarrativeBlock 打字机 on/off | 真实逐字与"显示全文" |
| 语义色文字开关（P1） | 演示"状态不唯色" | 切换图标/文字叠加 |
| 令牌搜索/筛选（P1） | 按组/关键字定位令牌 | 实时过滤画板 |

> demo 必须真实体现组件行为（状态切换、动效、焦点、对比），**不得为静态截图或图片**。

## 六、非目标（明确排除）

- **不实现任何游戏玩法/产品功能**（剧情推进、战斗结算、地图探索、背包、任务流转等）。
- **不改动 `app/game/*` 业务逻辑**（含 `StoryPanel` 滚动/打字机、`SettingsPanel`、`MorePanel` 等现有行为）。
- **不做后端 / 网络 / 持久化存储**。
- **v1 不实现浅色纸卷双主题**（见第三节）。
- **不新增修仙/商城/战力/灵石等未被批准的玩法或视觉元素**（违反规范与 AGENTS.md 基线约束）。
- 与 `docs/requirements-ui-polish.md`（R1–R9）的关系：该文档的 R1–R9 均为游戏行为改造（属 `app/game/*`，本 PRD 排除）。本设计系统**仅提供**高对比/减弱动效令牌与交互规范供其消费，不实现其行为逻辑，避免重复。

## 七、约束

- **平台抽象（微信小游戏迁移准备）**：设计系统与 living demo 的令牌/组件实现，须经平台适配层访问能力（InputPort/LifecyclePort/SafeAreaPort/AudioPort/StoragePort/AssetPort 思路），**不允许**直接耦合 DOM、`window`、`localStorage` 或微信专有 API；living demo 为浏览器演示，但其结构须为小游戏迁移保留边界。
- **不增删玩法基线**：严格遵循已批准产品需求基线，设计系统仅做表现层令牌与组件，不引入玩法语义。
- **技术栈**：仓库为 vinext 1.0.0-beta.2 + React 19.2 + Tailwind CSS 4.2 + TS 5.9，部署 Cloudflare Workers；**不使用 MUI**，样式以原生 CSS 令牌 + Tailwind 4 为主（`app/globals.css` 现状）。设计系统与 demo 以**独立目录/路由**实现，不混入 `app/game` 业务逻辑。
- **一致性**：所有视觉取值须可追溯至说明书三/十一/十二/十三与 DESIGN.md；新增令牌须标注规范出处。
