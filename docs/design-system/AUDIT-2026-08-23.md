# 设计系统缺项与合理性复核

- 日期：2026-08-23
- 范围：`app/design-system/`、`docs/design-system/`、`tests/design-system.test.mjs`
- 方法：受控规范对账、令牌引用扫描、源码静态审查、专项测试、定向 ESLint 与生产构建

## 结论

设计方向与“暗色湿墨石、文本优先、直角细边、不唯色、移动优先、微信可迁移”基线一致，组件和平台抽象基础合理。本轮发现的问题主要是实现继续扩充后，规范、令牌引用和验证门禁没有同步更新，而不是整体视觉方向错误。

## 已发现并修正

| 等级 | 问题 | 影响 | 修正 |
| --- | --- | --- | --- |
| P1 | CSS 使用不存在的 `--ds-stack-sm` 与 `--ds-c-tertiary-container` | 证据卡间距和规范标题色声明失效 | 改用 `--ds-s-stack-sm` 与 `--ds-c-gold` |
| P1 | 战报使用不存在的 `--ds-c-secondary-container` / `--ds-c-tertiary-container` | 伤害与状态战报退回默认色，状态层级失真 | 伤害改用可读的 `--ds-c-error`，状态改用 `--ds-c-gold` |
| P1 | `border-bottom-opacity` 不是有效 CSS 属性 | 战报分隔透明度设置被浏览器忽略 | 删除无效属性，统一使用受控 1px 边框令牌 |
| P1 | 页面规范卡引用多个不存在或残缺的令牌名 | 规范无法作为开发依据，易复制错误 | 全部改成 `tokens.ts` 中的真实令牌，并禁止在规范卡复制 HEX |
| P1 | 页面规范只有 6 个维度 | 缺少触控/键盘、焦点与读屏、减弱动效、图像资源边界 | 扩为 10 维，6 个页面逐页补全交互、无障碍、动效和图像图标规范 |
| P2 | 演示 SVG 颜色在字符串中固化 | 高对比切换不影响插画，形成隐性第二色板 | 改为渲染时由 `tokenValue()` 注入当前令牌值 |
| P2 | 组件、展示区、平台和版本描述停留在初始方案 | 文档写 12 组件/7 区/Cloudflare，与当前 13 组件/9 区/EdgeOne 不一致 | 新增文档入口，明确 12 核心 + 1 媒体组件、9 区、双基线与当前发布方式 |
| P2 | 原测试只检查 CSS 是否硬编码颜色，没有检查令牌是否真实存在 | 未定义变量可以长期漏检 | 新增令牌唯一性、全源码变量引用、无效 CSS 属性和页面 10 维完整性测试 |

## 保留且合理的设计决策

- 暗色单主题作为 v1 真源；高对比是同主题模式，不额外创造浅色主题。
- 令牌通过 React `style` 注入 `.shj-ds` 作用域，避免污染全局变量。
- 12 个说明书核心组件保持契约，`IllustrationFrame` 作为媒体承载扩展，不篡改核心组件计数。
- 断点演示使用容器宽度，不读取或改写真实 `window`；真机安全区仍需另行验收。
- 朱砂只作危险重点；需要作为战报文字时使用达到正文对比度的 `--ds-c-error`。
- 派生的冷月蓝、苔绿、绛紫和赭橙保留 `specRef` 标记，并坚持状态不唯色。

## 尚未纳入本轮的边界

- `app/globals.css` 与实际游戏界面尚未全面迁移到 `--ds-*`；这是独立集成任务，不能在设计系统复核中批量替换。
- 本轮未改变游戏玩法、信息架构、存档或 `app/game/*` 业务逻辑。
- 演示用 SVG 只是承载示例，不是正式美术资产；正式资源仍需授权、稳定 ID、尺寸/包体预算、失败占位与微信资源映射。
- 第一轮 QA 文档是历史快照，其中的组件数量、行数和“尚未存在”描述不能继续当作当前状态；保留它用于追溯，不改写历史结论。
- 全仓 TypeScript 检查仍会被 `app/game/*` 和 `worker/index.ts` 的既有错误阻断；本轮以设计系统专项测试、定向 ESLint 与生产构建判断当前范围。

## 后续建议

1. 新建独立 ADR 评审 `globals.css`/游戏页面向设计令牌迁移，按页面逐批替换并保留视觉回归基线。
2. 确定正式字体资源策略前继续使用系统回退栈；微信包体预算批准后再决定自托管字体子集。
3. 接入正式插画后建立资源清单，记录版权、哈希、宽高比、焦点位置、替代文本和低内存版本。
4. 在有条件的设备环境完成 iOS Safari、Android 中低端机与微信真机的触控、安全区、字体回退和减弱动效验证。
