======================================================================
〇、已完成UI调整与现状基线
======================================================================

本节记录当前原型已经完成的UI与交互调整。后续使用Stitch生成界面、继续进行UI设计或实现新页面时，必须继承这些行为，不得在没有批准变更的情况下退回旧方案。视觉稿可以优化表现，但不得改变本节描述的信息关系、阅读顺序和交互结果。

1. 整体视觉方向

当前已经采用“太古神话／山海异闻”氛围：以深墨绿、赤铜和土金色为主，配合印记、雨雾、古卷与异兆感装饰，弱化普通网页、现代后台和通用面板感。后续页面必须延续同一视觉系统。

2. 手机优先布局

（1）手机浏览器是当前优先适配目标，默认使用竖屏750×1334 px（@2x）母版。
（2）手机端使用底部固定主导航，并缩减顶部栏和角色信息占用。
（3）已经控制横向溢出，页面不得出现左右滚动。
（4）剧情阅读、选择和档案内容以单列为主，满足单手操作。
（5）桌面端在同一信息架构上响应式扩展，不另建行为分叉。

3. 剧情阅读区的消息结构

（1）NPC对话固定在左侧，以左侧对话气泡展示，并标注“角色名 · 对话”。
（2）玩家已经做出的内容保留在右侧气泡，按语义标注“你 · 说话”或“你 · 行动”。
（3）旁白使用全宽正文排版，不放入普通对话气泡。
（4）异兆和系统记录使用独立的居中提示样式，与NPC对话、玩家内容和普通旁白明确区分。
（5）尚待选择的选项靠右显示，采用类似聊天框的行动按钮，并明确标示“说话”或“行动”。
（6）每个新节点以“最新剧情”分隔线标记，帮助玩家辨认历史内容和当前新增内容。
（7）左右位置不是装饰性选择：左侧始终代表NPC表达，右侧始终代表玩家已做或将做的表达／行动。

4. 剧情展开节奏

（1）新剧情默认逐字显示，目标速度约每秒30—36个汉字。
（2）逗号、分号、句号、问号、感叹号等句末或分句标点允许加入短暂停顿，形成自然阅读节奏。
（3）逐字展开期间，本节点待做选项暂时不可点击，避免内容尚未完整呈现时误触跳转。
（4）展开期间必须提供“显示全文”按钮，玩家可立即跳过动画并阅读完整内容。
（5）逐字效果只作用于最新剧情，不重新播放历史剧情。
（6）开启“减弱动效”时，不进行逐字播放，直接显示完整内容并开放可用选项。

5. 阅读位置与历史回看

（1）做出选择进入新节点后，页面只自动定位一次到该节点的“最新剧情”起点。
（2）不得在逐字过程中持续抢夺滚动位置，也不得把玩家强制吸附到页面底部。
（3）历史剧情不清除、不折叠、不替换，玩家可以自由上下翻看完整对话和行动记录。
（4）当玩家离开最新区域后，提供“回到最新”按钮；触发后返回当前剧情末尾或当前可选操作区。
（5）切换到山海志、行囊、人物等二级页再返回卷册时，应恢复先前阅读位置。

6. 山海志、人物与行囊的三级结构

三个档案模块统一使用以下信息结构：

类别切换／下拉选择 → 子项列表 → 点击打开详情卡片。

禁止在主页面直接平铺所有条目和全部详情。

分类基线：
（1）山海志：异象、人物、器物、材料、异兽、地理。
（2）人物：按势力分类。
（3）行囊：装备、行旅、材料、工具、线索、异物。

手机端优先使用下拉选择或可横向滚动的类别标签、单列子项列表和详情弹窗／底部详情卡。桌面端可扩展为分类、列表、详情三栏，但信息层级保持一致。

7. 角色创建

（1）保留天性和缺陷选择。
（2）接入剧情内容包中的8种出身：猎户、山民、巫祝学徒、商旅遗孤、九黎流民、祭司之后、流亡贵胄、无名之人。
（3）创建顺序固定为：出身 → 天性 → 缺陷 → 名字。
（4）未建立角色前，剧情选项不可推进，并明确提示需要先完成角色创建。

8. 信息密度控制

（1）移动端隐藏或压缩非核心说明，优先保留剧情、选择、角色状态和底部导航。
（2）条目详细资料放入详情弹窗、底部卡片或二级页，不在主阅读页面堆积。
（3）隐藏只针对重复或辅助信息，不能隐藏关键条件、危险状态、错误原因和操作结果。

9. 无障碍与阅读设置

（1）已经保留正文字号、正文行距、高对比度和减弱动效设置。
（2）设置修改后应即时生效。
（3）开启“减弱动效”后，新剧情直接显示完整内容，不逐字播放。
（4）逐字显示期间的“显示全文”必须可通过触摸和键盘操作，并具有明确的读屏标签。
（5）待逐字播放完成后才开放的选项，需要向读屏说明当前暂不可用的原因。

10. 微信小游戏表现层适配基线

（1）默认界面继续使用竖屏750×1334 px（@2x）母版，即375×667 CSS px逻辑视口；运行时必须基于实际安全区、屏幕方向、像素比和可用宽高自适应，不能按固定750×1334物理屏幕硬编码。
（2）手机浏览器与微信小游戏共用同一信息架构、阅读顺序、状态文案、操作逻辑和可访问性语义；平台差异只能存在于输入、安全区、资源、音频、生命周期和存储适配层。
（3）顶部栏、角色摘要、剧情滚动区、底部主导航、待做选择、详情弹窗和战斗操作栏均必须避开刘海、圆角、状态栏和底部手势区；可交互控件不得被裁切或落在难以触达区。
（4）底部固定主导航和操作栏的高度必须包含动态底部安全区；正文、选择和地点卡必须预留足够底部空间，禁止被固定栏遮挡。
（5）触摸、拖动、点击、取消、返回和前后台切换通过统一输入与生命周期接口处理；剧情逐字播放、地图定位脉冲、音频和抽屉过渡在隐藏时可暂停，并在恢复后保持正确阅读与选择状态。
（6）字体、图标、纸张纹理和背景资源需要提供包体可控的本地资源或降级方案；不得依赖运行时外链图片、浏览器专属能力或未核验的Web API。
（7）减弱动效、高对比度、字号和行距设置跨平台保持相同效果；减弱动效时直接显示完整剧情，并立即开放可用选项。
（8）微信小游戏阶段必须至少覆盖iOS与中低端Android真机，验证安全区、触控坐标、文本换行、底部导航、滚动回看、抽屉、详情卡、存档恢复和前后台切换。

一、项目概述
======================================================================

1. 项目名称

《山海异闻录：天地未定》

2. 第一卷信息

卷名：《黑雨》
副标题：赤水有尸，天上少了一轮太阳

3. 产品类型

单机优先叙事RPG、文字MUD表达、分支剧情、轻策略战斗、长期世界状态模拟。

4. 当前目标平台

（1）手机浏览器，竖屏为默认体验。
（2）桌面浏览器，使用响应式扩展布局。
（3）后续保留迁移至微信小游戏的界面和平台抽象边界。

5. 核心体验循环

看见异常 → 理解规则 → 进行准备 → 作出代价明确的选择 → 承受长期后果 → 记录认知 → 带着新认知重新观察世界。

6. UI的核心职责

（1）支持长篇中文叙事的持续、舒适阅读。
（2）帮助玩家观察环境、人物、器物和规则线索。
（3）明确区分普通选择、特殊选择、锁定选择和不可逆选择。
（4）用克制方式表现关系、认知、资源和世界状态变化。
（5）让山海志、行囊、人物关系和世界状态成为叙事的一部分。
（6）避免传统手游大厅、页游按钮海洋和数值战力中心化表达。

======================================================================
二、强制产品原则
======================================================================

1. 剧情优先于数值

数值只服务于人物选择和世界规则，不能成为界面的绝对视觉中心。不得使用巨大战力数字、夸张伤害数字、满屏属性增长或“战力＋9999”式反馈。

2. 知识本身就是战斗力

界面必须表现“未知—传闻—实证—洞彻—余响”的认知变化。知识影响玩家是否应该行动、何时行动和如何行动，而不仅是属性加成。

3. NPC不是任务工具

人物界面不能将NPC处理成任务发布器或好感收集卡。重要NPC必须表现自身目标、状态、秘密、关系网络和可能失败的人生。

4. 珍贵物品都有故事

重要物品必须展示当前认知名称、感官描述、来源、用途、代价、唯一性和故事钩子。不得只展示品质颜色和属性数字。

5. 玩家是在经历神话

界面不能像百科网站一样把神话真相一次性陈列出来。信息必须随着玩家经历、证据和选择逐层显形，并允许互相矛盾的来源并存。

三、默认画板、逻辑尺寸与屏幕自适应
======================================================================

1. 默认设计画板

设计稿尺寸：750×1334 px
像素倍率：@2x
对应逻辑尺寸：375×667 CSS px
默认方向：手机竖屏
页面形态：响应式长页面，不限制内容总高度

重要换算原则：设计稿2 px＝前端1 CSS px。不得将750 px直接作为前端CSS视口宽度。

换算示例：

750×1334 px＝375×667 CSS px
32 px设计稿边距＝16 CSS px
88 px触控区域＝44 CSS px
32 px正文字号＝16 CSS px
128 px底部导航＝64 CSS px

2. 重点适配视口

最低兼容宽度：360 CSS px
默认逻辑视口：375×667 CSS px
全面屏手机：390×844 CSS px
Android大屏：412×915 CSS px
平板验证：834×1194 CSS px
桌面验证：1280×800、1440×1024、1600×1000 CSS px

3. 响应式断点建议

（1）≤720 CSS px：手机单主栏＋底部导航＋角色抽屉。
（2）721—1050 CSS px：角色栏＋中央阅读区，右侧功能栏折叠。
（3）>1050 CSS px：桌面三栏。
（4）≤720 CSS px且视口高度≤760 CSS px：压缩章节装饰区和非关键信息，不压缩正文可读性与触控尺寸。

4. 360—374 CSS px适配规则

（1）左右逻辑边距保持16 px。
（2）主标题使用27—28 px。
（3）隐藏版本号和纯装饰性副信息。
（4）所有双列卡片改为单列。
（5）底部导航文字不得省略。
（6）长选项自动增高，不截断，不用省略号隐藏关键动作。

5. 375—389 CSS px适配规则

（1）使用750×1334母版比例。
（2）正文默认16 px。
（3）主标题约30 px。
（4）普通选择逻辑高度56—68 px。

6. 390—429 CSS px适配规则

（1）左右边距可增加至18—20 px。
（2）档案列表可多显示一行来源或状态信息。
（3）角色摘要条可以保留地点和时辰。

7. ≥430 CSS px和平板适配规则

（1）不得简单同比放大所有元素。
（2）正文最大宽度限制在680—720 CSS px。
（3）山海志、人物、行囊等档案页可以转为双栏。
（4）地图可以增加地点详情栏。
（5）底部导航可以转换为侧栏。

8. 桌面扩展布局

顶部栏：68 CSS px。
左侧角色栏：260—280 CSS px，建议270 px。
中央阅读区：弹性宽度，正文实际阅读宽度640—720 px，最大不超过760 px。
右侧功能栏：248—270 CSS px，建议260 px。
中央区左右内边距：42—96 CSS px，根据窗口宽度变化。

四、手机竖屏总体结构
======================================================================

1. 顶部安全区

（1）背景延伸到屏幕最顶端。
（2）有效按钮、标题和角色状态避开刘海、挖孔和系统状态栏。
（3）使用动态safe-area-inset-top，不硬编码具体状态栏高度。

2. 顶部导航栏

设计稿基础高度：116 px，对应逻辑58 px，另加顶部安全区。

内容：
（1）左侧：朱砂方印“异”＋“山海异闻录”。
（2）中间：当前卷章，可在窄屏隐藏副标题。
（3）右侧：存档、设置。
（4）单个图标按钮触摸区域不小于88×88设计像素。
（5）顶部栏为暗黑半透明材质，滚动时吸顶。

3. 角色状态摘要条

展开高度：112—136设计像素。
收起高度：80—96设计像素。

内容：
（1）角色头像或抽象剪影。
（2）姓名、出身、年龄、地点。
（3）生息、精力、定力的紧凑数字摘要。
（4）流血、重伤、污染、恐惧等危险状态常驻。
（5）点击后打开角色详情抽屉。
（6）普通状态下允许随正文滚动收起。

4. 主阅读区

（1）左右设计稿边距32 px，对应逻辑16 px。
（2）宽屏手机可增加至40设计像素。
（3）使用连续卷册式单栏阅读，不嵌套多层卡片。
（4）章节标题、正文、对话、反馈和选择垂直排列。
（5）选择必须跟在对应剧情段落之后，不得悬浮遮挡正文。
（6）底部预留导航栏、安全区和至少32设计像素额外空间。

5. 底部导航

基础高度：128设计像素，对应逻辑64 px，另加底部安全区。

固定五项：
（1）卷册。
（2）舆图。
（3）山海志。
（4）行囊。
（5）更多。

要求：
（1）图标和文字同时显示。
（2）激活状态使用朱砂线、印记或结构变化，不能只改变颜色。
（3）二级页面返回后必须恢复原正文滚动位置。
（4）底栏不得遮挡最后一个选项、Toast或确认按钮。

======================================================================
五、上古神话神秘视觉风格
======================================================================

1. 核心视觉概念

天地未分明，神话尚未定名，黑雨正在洗去旧日的记录。

视觉应当神秘而非猎奇，古老而非陈旧仿古，神圣但不金碧辉煌，黑暗但保持文字清晰。玩家应感到世界中存在尚未被理解的规则、禁忌、祭祀、天象和被抹去的历史。

2. 风格关键词

现代东方神话、古籍质感、极简文字MUD、黑雨、赤水、扶桑、十日未临、三道影子、冷铜、旧金、朱砂、暗绿、盐霜、焦木、泥土、旧石、残简、结绳、拓印、水浸墨迹。

3. 推荐视觉母题

（1）黑雨形成的细密斜线。
（2）赤水倒流产生的水纹。
（3）十轮太阳的不完整圆环。
（4）三道错位影子。
（5）扶桑枝叶剪影。
（6）残缺日名和骨牌刻痕。
（7）旧铜、盐霜、焦木和湿泥质感。
（8）祭祀结绳、石刻、陶纹。
（9）被水浸开的朱砂墨迹。
（10）山峦、河道、异兽的极弱轮廓。

所有装饰应像世界留下的痕迹，而不是贴在界面上的现代装饰贴纸。

4. 禁止视觉方向

（1）绿色终端、黑客界面、DOS模拟器。
（2）高饱和金红页游按钮。
（3）商城、首充、礼包、签到、战力榜、满屏红点。
（4）霓虹描边、宝石按钮、大面积发光和持续呼吸光。
（5）通用仙侠大厅、漂浮仙山、金色龙凤框、翅膀和法阵堆砌。
（6）二次元抽卡、Q版异兽和收集式人物卡。
（7）恐怖猎奇化的尸体、祭祀和文化符号。
（8）企业后台、数据仪表盘和无意义卡片海洋。
（9）将关键中文文字烘焙进背景图片。
（10）仅靠颜色区分状态。

冷月灰蓝／accent-moon：#76858A，用于定力、梦境和未知。
普通边框／line-default：rgba(207,184,128,.22)。
强化边框／line-strong：rgba(216,180,107,.48)。
模态遮罩／overlay：rgba(2,6,4,.72)。

2. 状态表达

成功：暗苔绿＋成功图标＋“已完成”。
警告：赭金＋警告图标＋“需要确认”。
危险：朱砂＋危险图标＋“不可逆”或具体后果类别。
信息：旧金或灰蓝＋信息图标＋“新见闻”。
锁定：低明度灰褐＋锁形图标＋条件类别。

3. 高对比模式

（1）背景接近#080A08。
（2）主文字接近#FFF8E6。
（3）普通正文对比度至少4.5:1。
（4）大型文字、图标、边框和焦点至少3:1。
（5）降低或关闭背景纹理。
（6）选择、聚焦、锁定、危险状态仍必须通过形状和文字区分。

2. 750×1334设计稿字号

卷／页面主标题：56—64 px，逻辑28—32 px，行高1.2—1.3。
二级页面标题：44—52 px，逻辑22—26 px，行高1.3。

说明文字：24—26 px，逻辑12—13 px。

3. 正文规则

（1）中文正文默认16 CSS px。
（2）建议行高1.75—1.95。
（3）段落间距16—24 CSS px。
（4）叙事段落可首行缩进2字，对话不缩进。
（5）不得使用强制两端对齐造成异常字距。
（6）支持Unicode、字体回退、中文标点禁则和未来本地化。
（7）正文允许调整至默认字号的90%—130%。
（8）行距允许1.5—2.2，以0.1为一级。
（9）字号或行距增大后，容器必须自然增高，不得裁切。
（10）关键内容不得使用小于12 CSS px的字号。

十、页面模板
======================================================================

模板A：叙事阅读

适用：剧情、对话、探索、战斗、结算。
顺序：章节眉题 → 主标题 → 场景状态 → 历史剧情 → “最新剧情”分隔 → 最新旁白／左侧NPC对话／右侧玩家记录 → 居中异兆或系统记录 → 右侧待做选择 → 即时回响 → 自动存档状态。

模板B：档案浏览

适用：山海志、行囊、人物、成就。
顺序：页面标题 → 统计摘要 → 类别切换或下拉选择 → 子项列表 → 点击详情卡片 → 空状态。山海志、人物和行囊必须保持这一三级结构。

模板C：空间节点

适用：舆图、地点探索、副本空间。
顺序：当前地点说明 → 节点图 → 道路／线索连接 → 已知程度 → 时间／天气／危险／阵营 → 当前地点操作。

模板D：系统管理

适用：存档、设置、帮助。
顺序：页面标题 → 简短说明 → 分组列表 → 操作结果 → 错误与恢复 → 危险操作确认。

模板E：分步创建

适用：角色创建、卷末确认、多周目继承。
顺序：当前步骤 → 选项卡 → 选中详情 → 上一步／下一步 → 进度 → 最终摘要与确认。

======================================================================
十一、核心页面详细要求
======================================================================

1. 启动与继续游戏

目标：玩家在进入后快速理解作品身份和继续方式。

内容：
（1）朱砂品牌印记和游戏标题。
（2）第一卷《黑雨》与副标题。
（3）黑雨中的杳湾、赤水或桑林剪影。
（4）主操作：“继续卷册”或“立身入世”。
（5）次级操作：读取存档、导入存档、阅读设置。
（6）最近存档摘要：章节、地点、角色名、年龄、游戏时间、最近关键选择、内容版本。
（7）本地优先说明：“当前版本不需要登录，进度保存在本机。”

状态：首次进入、有自动存档、坏档但有恢复点、本地存储不可用、内容加载中、内容版本不匹配。

2. 角色创建“立身入世”

第一步：出身

猎户、山民、巫祝学徒、商旅遗孤、九黎流民、祭司之后、流亡贵胄、无名之人。

每张出身卡显示：名称、一句生活场景、擅长发现的信息、初始物品、社会风险、小型属性修正。属性修正置于最弱层级，不得把出身表现成职业或难度选择。

第二步：天性

谨慎、好奇、仁厚、狠决、多疑、执拗。

说明天性影响自动反应、关系增长、压力恢复和部分选项，不是善恶值。

第三步：缺陷

首批可用：怕水、夜盲、旧伤、不善言辞。

每项显示当前限制、独特观察方式和“可能在相关经历中形成新的应对之道”，但不剧透具体反转。

第四步：姓名与总览

姓名最多8个汉字，默认“无名之人”。展示出身、天性、缺陷、初始物品和开场差异。最终按钮为“立身入世”。说明：“这些选择会带来不同信息、选择和代价，而不只是数字变化。”

手机每次只显示一个步骤。创建顺序固定为“出身 → 天性 → 缺陷 → 名字”。可使用全屏流程或最大90dvh底部抽屉。未建立角色前，剧情选项不可推进。

3. 主剧情阅读页

示例标题：“雨在落下以前”。

页面顺序：章节眉题、主标题、十日未临的弱圆环装饰、历史剧情、“最新剧情”分隔、最新旁白、人物对话、玩家历史行动、异兆／系统记录、条件回响、待做选择。

消息排版规则：NPC对话使用左侧气泡并标注“角色名 · 对话”；玩家已经选择的说话或行动使用右侧气泡并标注“你 · 说话”或“你 · 行动”；旁白使用全宽正文；异兆和系统记录使用居中提示；待做选择靠右并标示“说话”或“行动”。

新剧情以每秒约30—36字逐字展开，句末短暂停顿。展开期间选项暂不可点击，同时提供“显示全文”。进入新节点后只自动定位一次到“最新剧情”起点，历史剧情完整保留。玩家离开最新区域后显示“回到最新”。减弱动效开启时直接显示全文。

普通选项示例：
检查赤金箭
辅助说明：推进调查

特殊选项示例：
【灵识】观察雨滴里的十个红点
辅助说明：来源：角色能力

物品选项示例：
【羿的旧弓】对照箭杆上的受力痕迹
辅助说明：来源：已装备器物

锁定选项示例：
【心志】追问空缺的第十个位置
辅助说明：条件：你的记忆正在排斥这次追问

锁定项可显示存在和条件类别，但不得显示“心志必须达到8”等精确门槛。

4. 选择组件

在750 px画板中，默认宽度为686 px，即页面宽度减去左右各32 px。

建议结构：
左侧编号区：64设计像素。
中间文字区：弹性宽度。
右侧状态区：56设计像素。
上下内边距：24—28设计像素。
左右内边距：24设计像素。
选项间距：16设计像素。
普通选项高度：至少112设计像素。
双行选项高度：至少136设计像素。

变体：普通、特殊来源、物品来源、锁定、危险／不可逆、已选择、禁用、加载、焦点、按压。

5. 重大选择确认

仅用于真正不可逆或明显影响人物、地点、唯一物、阵营和世界状态的选择。

必须显示：
（1）“此选择将改变……”及明确的后果类别。
（2）不泄露隐藏剧情。
（3）主按钮使用具体动作，例如“折断赤金箭”。
（4）次按钮使用“再想一想”。
（5）禁止只使用“确定／取消”。
（6）日常选择不得滥用确认框。

6. 选择反馈和世界回响

即时反馈：短Toast，例如“阿禾记住了你没有弃下白羊”。
段落内反馈：关系发生变化、获得新见闻、某地出现新异常。
长期回响：通过新对话、地点变化、人物反应或卷末结算体现。

Toast位于底部导航上方，持续2.5—4秒，可由读屏播报，不得遮挡选项。

7. 舆图

舆图是“已知地点和关系的记录”，不是现代GPS地图。

显示：当前地点、已抵达、传闻、已知但不可到达、未显形、道路关系、时辰、天气、危险、阵营控制和已知程度。

第一卷地点示例：杳湾、北滩无名尸、东桑林、旧盐井、赤水渡口、倒船腹舱。

状态必须通过图形和文字共同表达：已抵达、剧情线索、危险、尚待剧情开启、当前所在。

8. 战斗／遭遇

战斗采用文字回合或节拍制。重点是敌方意图、环境、知识、准备和是否应该战斗，不使用巨型Boss血条作为中心。

结构：
（1）遭遇名称。
（2）敌方行为和意图提示。
（3）环境变化：火势、水位、黑雨、日照、鼓声、地形。
（4）玩家资源和状态。
（5）可用知识和准备。
（6）行动选项。
（7）本节拍结果。
（8）撤退路线。

行动：攻击、防御、移动、观察、使用物件、同伴指令、交涉、仪式、撤退。

认知不足示例：“含晦背上的人嘴正在同时吸气。”
认知充分示例：“它将在下一节拍吞食最近一次未说完的话；保持沉默或释放囚雨芦可打断。”

击杀、驱赶、封存、谈判、绕行、救援和撤退均可成为有效结果。

9. 山海志

分类：异兽、人物、神祇、器物、材料、地点、事件、俗说。

认知层级：初见、传闻、实证、洞彻、余响。

每层显示：来源声音、内容、可靠性、矛盾说法、解锁事件、可能影响的检定或剧情。

示例“黑雨”：
初见／玩家见闻：雨滴如冷铜，水面映出十个红点。
传闻／杳湾众口：不同人物对来源有互相冲突的说法。
实证／行证录：经过材料和地点证据验证的性质。
余响／后世异说：卷末或多周目出现的历史版本。

未解锁层级只显示轮廓和“尚无可信记录”，不得提前显示摘要。山海志应像正在形成的知识档案，而非怪物图鉴卡册。

10. 行囊和装备

完整装备栏预留：主手、副手／仪式手、衣甲、足具、护符、工具、随身信物。

重要物品显示：当前认知名称、感官描述、来源、物性、数量、耐久、可用条件、收益、代价、不生效原因、唯一性、关联山海志。

材料显形示例：
初见：“烧不尽的灰”。
传闻：“日灰”。
实证：“扶桑烬”。
洞彻：与被抹去的白昼有关。

实体ID不变，只改变玩家认知名称和说明。界面可使用层级轨迹或逐层展开表现显形过程。

11. 人物和关系

人物列表显示姓名、身份、势力、地点、状态和最近可观察反应。

人物详情分别显示：好感、信任、敬重、畏惧、债务、价值观一致度。不得将全部关系压缩为一个爱心或单一好感数字。

同时显示人物当前目标、已知秘密、关系来源、近期变化、山海志入口、重要历史。无法确认的信息标记“未知”，不留无意义空白。

12. 任务和事件记录

弱化清单打卡，强化事件脉络。每项显示事件名称、当前问题、已知线索、涉及人物、地点、阶段、最近变化、是否有时限和可能继续方向。

禁止“0／10击杀野狼”式任务结构。

13. 存档和迁移

Demo提供：自动存档、3—5个手动槽（建议5个）、写入、读取、导出JSON、导入JSON、删除、重新开始。

每个存档显示：角色名、章节、地点、年龄、游戏时间、内容版本、保存时间、最近关键选择、来源、健康状态。

异常状态：空槽、坏档、旧版本待迁移、存储空间不足、写入失败、导入格式错误、导入成功但有兼容提醒、恢复点可用。

删除、覆盖和重新开始必须二次确认并使用具体动作名称。

Demo只显示：“当前进度保存在此设备，本版本不接入账号或云同步。”不得显示假云存档按钮。

14. 阅读与无障碍设置

阅读：正文字号、正文行距、高对比、关闭文字渐显、简化背景纹理、对话人物名强化、释义操作方式。

动效：减弱界面动效、关闭轻微震动、关闭背景雨滴动画。

声音：总音量、环境音、音乐、音效。读屏不受游戏音量控制。

操作：键盘快捷键、焦点高亮、自动滚动、恢复默认。

设置改变后立即在预览段落中生效，并按设备／存档策略持久化。

======================================================================
十三、交互、键盘和无障碍
======================================================================

1. 触摸

（1）最小触摸面积88×88设计像素，即44×44 CSS px。
（2）相邻触摸控件至少间隔16设计像素，即8 CSS px。
（3）处理按下、移动、取消和释放全过程。
（4）关键操作防止重复提交。
（5）不依赖复杂手势完成主流程。

2. 键盘

（1）主流程可仅用键盘完成。
（2）Tab顺序与视觉顺序一致。
（3）焦点使用2 CSS px朱砂或高对比旧金轮廓，外偏移3 CSS px。
（4）模态打开后焦点进入模态，关闭后返回触发按钮。
（5）无焦点陷阱。

3. 读屏

（1）页面、标题、导航、列表、对话和选项使用正确语义。
（2）状态变化和错误可被播报。
（3）Toast使用状态播报，不重复打断长文本。
（4）视觉顺序与读屏顺序一致。
（5）图片有替代文本。

4. 释义

桌面支持悬停和键盘聚焦；手机支持点击或长按。关键解释不能仅存在于悬停状态。

5. WCAG目标

以WCAG 2.2 AA为基线。普通文本对比度至少4.5:1；大字、图标、焦点和状态边界至少3:1。关键信息不得只靠颜色、声音或震动表达。

十四、动效与声音表现
======================================================================

1. 允许动效

（1）极慢背景黑雨。
（2）章节标题轻微淡入。
（3）新见闻以短促印记显形。
（4）关系或世界变化使用克制的墨迹扩散。
（5）选择按压80—120 ms。
（6）页面切换180—260 ms。
（7）抽屉220—300 ms。

2. 禁止动效

（1）不可跳过、持续抢夺滚动位置或阻塞历史回看的长段逐字播放。
（2）持续呼吸发光按钮。
（3）大面积粒子。
（4）镜头晃动和高频闪烁。
（5）影响快速阅读的长转场。

3. 减弱动效模式

移除雨滴移动、视差、缩放和墨迹扩散；页面直接淡入或无过渡；最新剧情立即完整显示，不执行逐字播放；可用选项直接开放；仍保留必要状态变化，但不依赖动画传达。

4. 声音

可使用雨声、火声、鼓声、风声强化节奏，但均可关闭并独立调节。声音不能成为关键状态的唯一反馈。

十八、Stitch全局母提示词
======================================================================

为中国上古神话叙事RPG《山海异闻录：天地未定》设计高保真手机竖屏UI。

默认设计画板必须为750×1334px，@2x，对应375×667 CSS逻辑尺寸。界面需要屏幕自适应，最低支持360 CSS px宽度，并适配375、390、412 CSS px手机、全面屏安全区、刘海、挖孔和底部手势区域。不要将750px直接作为前端CSS宽度。

游戏第一卷为《黑雨》，副标题“赤水有尸，天上少了一轮太阳”。游戏是一款以长篇中文文字为主要媒介的单机叙事RPG，不是传统手游大厅。核心体验是观察异常、理解规则、准备、选择、承担后果和记录新的认知。

视觉风格必须具有上古神话的神秘感：天地未定、神话尚未被命名、黑雨正在洗去旧日记录。结合现代东方神话、古籍质感和极简文字MUD。使用黑雨、赤水、扶桑、十轮残日、三道影子、旧铜、盐霜、焦木、泥土、残缺日名、祭祀结绳和水浸朱砂等抽象元素。

整体色调为玄黑、暗绿、旧纸浅金、朱砂、赤铜和苔色。背景深色而克制，正文必须清晰。纹理透明度低，不得干扰阅读。不要绿色终端，不要霓虹，不要页游金色按钮，不要仙侠手游大厅，不要商城、战力、礼包、红点和高饱和卡片海洋。

使用以下主要颜色：背景#080D0A；阅读区#0D1510；一级面板#172019；选项面板#263127；主文字#E5D9BC；次文字#ADA58F；朱砂#D15A42；古金#C29A58；苔色#718469。

默认竖屏结构：顶部安全区；58 CSS px吸顶导航栏；可折叠角色状态摘要；单栏长篇剧情阅读区；64 CSS px固定底部导航和底部安全区。

底部导航包含：卷册、舆图、山海志、行囊、更多。每项同时使用图标和文字。角色信息通过顶部摘要条和抽屉展开。危险状态常驻顶部。

设计稿左右边距32px，对应16 CSS px。正文设计稿字号32px，对应16 CSS px，行高56—62px。章节主标题56—64px。最小触摸区域88×88px。普通选项高度至少112px，双行选项至少136px。所有长文字和选项必须自动增高，不得裁切。

剧情页面保留完整历史记录，并以“最新剧情”分隔新节点。NPC对话固定为左侧气泡，标注“角色名 · 对话”；玩家已经做出的说话或行动固定为右侧气泡，标注“你 · 说话”或“你 · 行动”；旁白使用全宽正文；异兆和系统记录使用居中提示；待做选项靠右并标注“说话”或“行动”。选项必须跟在对应段落后，不得悬浮遮挡正文。

新剧情默认以每秒约30—36个汉字逐字显示，句末短暂停顿。展开期间选项暂不可点击，并提供“显示全文”。进入新节点时只自动定位一次到“最新剧情”起点，不持续抢夺滚动位置。历史剧情不得清除、折叠或替换，提供“回到最新”按钮。减弱动效模式下直接显示全文。

选择组件必须包含普通、特殊来源、物品来源、锁定、不可逆、禁用、聚焦、按压和已选择状态。示例：“检查赤金箭”；“【灵识】观察雨滴里的十个红点”；“【羿的旧弓】对照箭杆上的痕迹”。锁定选项只提示条件类别，不泄露精确数值。

设计以下移动端页面：启动与继续游戏；分步角色创建；主剧情阅读；重大选择确认；舆图；文字节拍制战斗；山海志；行囊与装备；人物与多维关系；任务与事件记录；本地存档、导入和导出；阅读与无障碍设置；加载、空、锁定、离线、错误、坏档和恢复状态。

山海志、人物和行囊统一使用“类别切换／下拉选择 → 子项列表 → 详情卡片”的三级结构，不在主页面平铺全部内容。山海志必须像逐层形成且允许矛盾并存的古老知识档案，而不是怪物卡册。物品必须体现从未知感官描述到真实名称、用途和代价的认知显形过程。

目标符合WCAG 2.2 AA。提供高对比度、字号90%—130%、行距1.5—2.2、关闭文字渐显、减弱动效、独立音量、明显键盘焦点和不依赖颜色的状态表达。
