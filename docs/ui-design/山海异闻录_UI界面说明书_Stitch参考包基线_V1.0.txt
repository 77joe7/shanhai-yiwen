《山海异闻录：天地未定》UI界面说明书
Stitch参考包基线版 V1.0

用途：将 `stitch_shan_hai_mobile_mud_interface (1).zip` 中已确认的版式、视觉语言、元素组织、操作逻辑和层级关系，转换为《山海异闻录：天地未定》可执行的UI设计与实现规范。
适用范围：第一卷《黑雨》的手机浏览器优先原型；桌面浏览器响应式扩展；后续微信小游戏表现层迁移准备。
默认设计母版：750×1334 px，@2x；逻辑视口375×667 CSS px。

======================================================================
一、参考来源、适用边界与优先级
======================================================================

1. 参考来源

本说明书的视觉和结构依据以下参考包：

docs/ui-design/stitch_shan_hai_mobile_mud_interface (1).zip

包内包含以下五类页面及一份设计令牌文件：

（1）main_narrative_1：基础探索叙事日志。
（2）main_narrative_2：包含未知对象、认知层级和风险提示的叙事日志。
（3）exploration_map：全屏探索地图。
（4）combat_log：回合制战斗记录。
（5）character_quest_drawer：左侧角色／任务抽屉。
（6）shan_hai_chronicle/DESIGN.md：颜色、字体、间距、形状和组件说明。

2. 参考包的设计事实

参考包实际截图为约706×1600 px的竖向预览图，HTML页面本身采用流式移动端布局，而非声明一个固定画板。因此：

（1）本项目继续以750×1334 px（@2x）为设计母版。
（2）参考包的长截图只作为内容密度、结构节奏和视觉风格依据，不把706×1600当作前端固定屏幕尺寸。
（3）宽度、字号、固定栏位和安全区必须继续使用响应式逻辑，覆盖360、375、390、412 CSS px等手机视口。

3. 内容替换规则

参考包中出现“修为、灵石、灵兽、修行、昆仑镜碎片、青丘九尾、太虚剑意”等通用修仙示例。它们不构成《山海异闻录：天地未定》的产品需求。

必须保留的是：暗色古卷视觉、叙事日志结构、地图层次、战斗日志、侧抽屉、细线边框、信息权重和操作区域的组织方式。

必须替换的是：世界观文案、角色资源、物品、敌人、任务、导航名称、战斗行动和人物成长语义。替换后必须符合《黑雨》内容包和游戏设计说明书，不得擅自引入修仙等级、灵石货币、灵兽养成或门派玩法。

4. 冲突优先级

（1）当前批准的游戏设计说明书和剧情内容包决定玩法、数据和文案事实。
（2）当前已完成UI现状基线决定聊天式剧情、逐字展开、历史回看和三级档案的交互行为。
（3）本说明书和参考ZIP决定视觉样式、布局骨架、元素组织和表现细节。
（4）若参考包的表现与前两项冲突，保留视觉方法，调整信息语义和交互结果；不得为了复刻画面而回退已实现的产品行为。

======================================================================
二、设计定位与体验目标
======================================================================

1. 体验定位

这是一个“可阅读、可观察、可回看、可推理”的神话叙事界面，而不是传统手游大厅。它应像一册在暗处被翻开的古卷，又具有现代移动端清晰的操作边界。

2. 参考包所体现的核心气质

（1）数字古卷：以深色纸张、细小颗粒、留白、衬线文字和细金边构成阅读场。
（2）学者案头：界面克制、安静、权威，主要依赖文字、规则线和符号表达信息。
（3）低认知负担：主阅读区每次只突出当前叙事、当前观察或当前风险。
（4）神秘而非堆砌：异象通过留白、弱光、标签、逐层信息和不完整描述呈现，不以大量特效制造神秘。
（5）操作有边界：顶部承载全局入口，底部承载主操作，内容区专注叙事或空间，不与固定操作层争夺注意力。

3. 《黑雨》世界观适配

参考包的“墨色羊皮纸”必须转化为“黑雨洗过的旧纸、湿木、冷铜、盐霜和赤水夜色”。画面不应使用大面积金色宫殿、祥云、仙剑、神兽坐骑或玄幻商城式元素。

可使用的抽象母题：黑雨斜线、细粒噪点、被水浸开的朱砂、扶桑枝影、三道错位影子、十日残环、赤水波纹、骨牌刻痕、盐晶、结绳和残简边线。

三、设计令牌
======================================================================

1. 色彩

以下为参考包实际令牌与本项目语义。颜色可以为高对比模式提供替换值，但普通模式不得随意改成高饱和彩色界面。

画布／湿墨石 background：#17130F
最深容器 surface-container-lowest：#110E0A
低层容器 surface-container-low：#1F1B17
标准容器 surface-container：#231F1B
高层容器 surface-container-high：#2E2925
最高层容器 surface-container-highest：#39342F
主文字／旧丝绢 on-surface：#EAE1DA
次文字／雾纸 on-surface-variant：#CEC5B9
弱文字／残墨 outline：#979085
弱边框 outline-variant：#4C463D
主要可交互文字／旧丝 primary：#FFF2DE
主要填充／旧丝 primary-container：#E6D5B8
金色细节／焦金 tertiary-container：#F5D294
固定金色／进度 primary-fixed-dim：#D5C5A8
朱砂危险 secondary-container：#920703
危险文本 error：#FFB4AB
危险底 error-container：#93000A

《黑雨》补充色，仅用于有清晰语义的状态：

生命／伤势：朱砂与暗红。
精力／准备：焦金与暗赭。
定力／梦境／认知：低饱和冷月蓝，使用时必须附文字。
自然／地点／可采集：低饱和苔绿，使用时必须附文字。

2. 对比与使用比例

（1）大面积背景采用#17130F或更深层，不使用纯黑。
（2）正文采用#EAE1DA或接近该亮度的暖白，避免过度刺眼。
（3）边界线用#4C463D到#D5C5A8的低透明变体，不使用厚重面板阴影。
（4）金色用于标题、图标、进度和边框的局部强调，不能覆盖大面积正文。
（5）朱砂仅用于危机、伤势、不可逆提示、敌对威胁和重要历史印记。
（6）任何关键状态必须同时拥有文字、图标或结构变化，不能只依赖颜色。

3. 字体

显示标题：Noto Serif SC／思源宋体，36 px，700，行高1.2，字距0.1em。
大标题：Noto Serif SC／思源宋体，24 px，600，行高1.4。
手机标题：Noto Serif SC／思源宋体，20 px，600，行高1.4。
叙事正文：Literata或高可读中文宋体，18 px，400，行高1.8。
辅助正文：Literata或高可读中文宋体，14 px，400，行高1.6。
标签与系统信息：Source Serif 4／思源黑体，12 px，700，行高1，字距0.2em。

在750×1334 @2x画板中，默认正文字号对应32—36设计像素；移动窄屏可以降到逻辑16 px，但不得低于此值。标题可随空间缩小，正文和触控尺寸不得为适应短屏而缩小。

4. 间距

基础单位：4 CSS px。
紧密间距：8 px。
标准内容间距：16 px。
大段落间距：24 px。
页面边距：20 px。
窄内容沟槽：12 px。

叙事段落之间至少24 px；每个叙事节拍、观察结果、物品卡、当前风险之间以细线或24 px留白隔开。不要用连续卡片挤压内容。

5. 形状、边框与层次

（1）参考包的正式基线是直角，圆角为0。按钮、卡片、状态条、地图浮层和抽屉以方形／直角为主。
（2）若为适配现有项目而保留极轻微圆角，最大不得超过4 CSS px；不得做现代化大圆角卡片。
（3）深度由色调层和1 px细线制造，而非厚阴影。
（4）常规边框为金色30%透明度；悬停或聚焦时增强到60%或切换为旧丝色。
（5）关键卡片可用双线、顶部居中符号、切角或细朱砂印记增强，但不得增加大面积纹样。
（6）分隔线使用两端透明、中部淡金的渐变细线，模拟收笔的刷痕。

6. 纹理和动效

（1）全局可叠加5%透明度的细颗粒噪点，模拟旧纸或湿墨；该层不可阻塞交互。
（2）地图可以有极弱50 px网格，模拟古舆图的定位线。
（3）战斗区可有20 px点状阵列，模拟雨点、盐粒或祭坛尘屑。
（4）背景纹理只能加强层次，不得降低正文对比度。
（5）减弱动效模式关闭地图定位脉冲、浮层过渡、背景视差和逐字动画；保留即时状态变化。

======================================================================
四、全局信息架构与层级关系
======================================================================

1. 手机页面层级

层级0：全局背景、细颗粒纸张纹理、页面主题图层。
层级1：固定顶部栏、主内容滚动区、固定底部主导航或操作栏。
层级2：内容内的黏性状态区、地点信息卡、战斗资源区、回到最新按钮。
层级3：详情卡片、底部详情卡、确认框、命令／行动输入栏。
层级4：角色／任务侧抽屉和半透明遮罩。
层级5：错误、存档确认、导入、不可逆决定等模态对话框。

同一时刻应避免同时出现侧抽屉和第二个模态框；若详情由抽屉发起，优先在抽屉内展开二级内容或先关闭抽屉再打开详情。

2. 导航层级

一级：卷册、舆图、山海志、行囊、更多。

二级：

卷册：剧情记录、当前节点、回到最新、章节／卷册目录。
舆图：区域、地点、地点详情、探索动作。
山海志：类别、条目列表、条目详情、认知层级。
行囊：类别、物品列表、物品详情、装备槽。
更多：人物、事件／任务、阅读设置、存档、帮助。

三级：详情卡、认知层级、物品动作、人物关系轴、任务进度、地图地点动作、存档槽操作。

3. 参考包四导航的项目映射

参考包使用“探索／包裹／人物／卷轴”四项导航。项目不应复制其通用名称，而应保留其图标＋短标签＋底部等宽分布的表现方法，映射为以下五项：

卷册：当前叙事与历史记录。
舆图：探索地图和地点。
山海志：见闻、人物、材料、异兽和异象档案。
行囊：装备、物品、材料、工具和线索。
更多：人物、任务、设置、存档和帮助。

如屏幕宽度不足，标签字号可压缩，但不得只保留图标。当前页以亮旧丝图标、较亮文字和上缘／左缘细线共同表明；非当前页使用弱文字。

4. 侧抽屉的角色

参考包侧抽屉不是第二个完整主页面，而是“角色速览＋个人入口＋紧急任务查看”的上下文面板。项目中它承担：

（1）角色肖像、姓名、出身／身份、年龄、当前地点。
（2）核心资源和危险状态的摘要入口。
（3）角色详情、人物关系、事件／任务、行囊快捷入口。
（4）最近获得的关键物品或线索，不展示完整背包。
（5）当前主线和支线的简短卡片。

不可将云账户、货币商城、社交、广告或尚未批准的系统塞入抽屉。

======================================================================
五、全局框架与尺寸
======================================================================

1. 顶部栏

高度：64 CSS px，对应128设计像素；另加顶部安全区。

布局：左、中、右三列。左侧为菜单或返回；中间为“山海异闻录”或当前页面标题；右侧为角色入口、设置或当前页工具。标题必须视觉居中，不因左右图标宽度不同而偏移。

外观：#17130F底色，底部1 px低透明金线。标题使用宋体、暖白、较大字距。图标为旧丝或弱金，按下时仅出现轻微亮度和颜色翻转。

2. 主内容滚动区

顶部安全距离：顶部栏后至少16 px。
底部安全距离：底部固定栏或操作栏后至少24 px，加底部安全区。
左右边距：20 CSS px；最窄360 CSS px仍不低于16 px。
正文最大宽度：移动端100%，平板／桌面最大约672 px或2xl阅读宽度，居中显示。

3. 底部主导航

高度：60—64 CSS px，加底部安全区。
结构：等宽分配；图标在上、文字在下；每项最小44×44 CSS px。
背景：标准表面色；顶部1 px金色30%透明边线。
不得遮挡正文、选择、地图信息卡和战斗操作。

4. 底部操作栏

叙事命令栏或战斗操作栏位于主导航上方；页面若有固定底部操作栏，必须为内容滚动区预留其完整高度。

参考包的叙事命令栏包含：左侧“>”提示符、单行输入区域、右侧“执行”按钮。项目中应作为“输入意图／搜索已知线索”的可选能力或开发调试能力，不得取代已批准的剧情选择按钮。正式叙事主路径仍应把待做选项显示在剧情末尾右侧。

5. 侧抽屉

宽度：320 CSS px，最大不超过视口80vw。
位置：从左侧滑入，覆盖全高。
遮罩：全屏半透明黑色约50%—80%，可带轻度背景模糊。
关闭方式：右上关闭按钮、点击遮罩、Esc键。关闭后焦点返回菜单触发按钮。

======================================================================
六、卷册／主叙事界面
======================================================================

1. 页面目标

卷册是整个产品的默认主页面。参考包以连续的“叙事日志＋观察结果＋物品卡＋当前风险＋命令栏”组织信息。本项目将其适配为“完整历史记录＋最新剧情＋聊天式表达＋行动选择＋认知资料”的连续卷册。

2. 内容排序

从上至下按时间推进，但每个节点内部必须遵守以下阅读顺序：

（1）时间／地点／时辰元信息。
（2）全宽旁白，描述场景和可观察环境。
（3）左侧NPC对话气泡，标签为“角色名 · 对话”。
（4）右侧玩家既有说话或行动气泡，标签为“你 · 说话”或“你 · 行动”。
（5）居中异兆／系统记录，用于获得物品、认知变化、关系变化、世界状态变化和危险提示。
（6）观察、调查或发现的全宽叙事。
（7）物品／线索／未知对象卡。
（8）右侧待做选择，明确标记“说话”或“行动”。
（9）自动存档提示与下一节点到来前的分隔。

新节点开始位置使用“最新剧情”分隔。分隔由两端透明、中部淡金的1 px刷痕线和小型菱形／符号组成，不能用大面积标题条打断阅读。

3. 旁白

旁白为全宽暖白正文，使用18 px、1.8行高。第一段可通过时辰图标与全大写风格小标签引入，例如“第一日 · 清晨”“北滩 · 黑雨初落”。旁白不使用普通聊天气泡，不加重边框，以留白和细线形成节拍。

4. NPC对话与玩家记录

NPC对话固定左对齐，使用低层容器色或透明深纸色，细金边，标签显示人物名和“对话”。玩家既有选择固定右对齐，使用稍亮一层容器或更明显的旧丝边线，标签显示“你 · 说话”或“你 · 行动”。

左右位置必须稳定：左侧只代表他者表达，右侧只代表玩家已经作出的表达和将作出的行动。旁白和系统信息不占左右对话位置。

5. 观察节拍

参考包用眼睛图标＋“观察”标签分隔发现。项目中保留此模式，用于调查、感知、线索比对和认知解锁：

图标＋小标签“观察／检验／听闻／异兆” → 全宽发现文本 → 可选的条目卡。

标签色使用弱金或弱文字，不能比剧情正文更醒目。观察结果用精确但不泄露完整答案的文本表达。

6. 物品、线索与认知卡

参考包的资料卡结构应保留：1 px金边、深层容器、顶部居中小型类别符号、左侧标题、右侧方括号类别标签、下方感官描述。

项目示例：

标题：烧不尽的灰。
类别：[未知材料]。
描述：贴近皮肤会发暖，黑雨无法浇灭。
认知升级后标题变为：扶桑烬。

卡片只显示当前已知层级。未知性质显示“尚未证实”或“仍不可辨”，不能将未来解锁信息暗示为确定事实。

7. 异兆、系统记录与状态标签

异兆／系统记录居中显示，可使用步行、眼睛、雨滴、结绳、残日等小图标。标题标签如“当前”“异兆”“记录”置于正文上方。危险标签采用方括号形式，例如[危机]、[阴寒]、[伤势]、[关系变化]，维持文本中心的古卷风格，避免现代药丸Chip。

参考包的方括号标签可以使用1 px边线，但不做大圆角。朱砂只用于危机、伤势、不可逆和敌对；金色或暗苔色用于非危险状态。

8. 待做选择与意图输入

待做选择靠右显示，继承玩家气泡位置。每项必须显示动作短语、类型“说话／行动”、来源标签或锁定条件。普通剧情选择仍是主流程。

可选命令输入栏保留参考包样式：底边细线输入框、左侧“>”、右侧方形“执行”按钮。它只适用于批准后的自由意图、检索或调试，不得让玩家在必经剧情中必须猜命令词。

9. 逐字展开、回看与滚动

（1）新剧情默认约每秒30—36字逐字呈现，标点处短暂停顿。
（2）展开中，当前节点待做选项不可点击；同时提供“显示全文”。
（3）减弱动效时直接显示完整文本与可用选项。
（4）进入节点时只自动定位一次到“最新剧情”起点，之后不持续强制滚动。
（5）历史内容不得清除、折叠或替换。
（6）离开最新区域后提供“回到最新”按钮。

======================================================================
七、舆图／探索地图界面
======================================================================

1. 页面目标

参考包把地图设计为一张暗色古舆图：地形图层、弱网格、少量符号地点、中心玩家定位、右侧缩放工具和底部地点卡。本项目的舆图应保留这种“被探索记录过的世界”的感觉，不做现代GPS地图或开放世界任务清单。

2. 页面结构

顶部栏：返回／菜单、标题“舆图”、角色或设置图标。
地图画布：占满顶部栏和底部导航之间的可视区域，可拖动、缩放。
地图底图：深纸色与低饱和水墨地貌，叠加50 px弱网格。
地点标记：基于符号、名称和已知程度。
右侧工具：放大、缩小、回到当前位置，垂直排列。
底部地点卡：显示当前选中地点概览、环境描述和状态标签。

3. 地图标记

山／秘境：三角或山形符号。
聚落／祠屋／城：建筑或柱形符号。
林地：树形符号。
河流／水域：波线符号。
当前所在：实心定位标记＋淡金定位环。
未显形：不显示名称，或只显示模糊符号和传闻提示。

每个标记必须有可读文字；不要仅用图标。鼠标悬停可显示补充提示，手机点击则选中并打开地点卡。

4. 当前地点卡

位置：手机底部导航之上，左下对齐；不遮挡缩放按钮。
内容顺序：地点名 → 类型图标 →刷痕分隔线 → 2—3行环境描述 → 方括号状态标签 → 可执行探索动作。

《黑雨》示例地点：杳湾、北滩无名尸、东桑林、赤水渡口、旧盐井、倒船腹舱。地点描述必须根据时辰、天气、危险、阵营控制、已知程度和世界状态变化。

5. 操作逻辑

（1）拖动地图：仅移动画布，不能触发地点误点。
（2）捏合或缩放按钮：改变地图比例，需设最小／最大范围。
（3）回到当前位置：居中玩家标记，不改变当前地点。
（4）点击地点：选中地点、更新底部卡；只有已达成条件的地点才可进入或快速移动。
（5）锁定地点：可显示条件类别，但不展示完整答案。
（6）减弱动效：关闭定位环脉冲，保留静态当前位置标记。

======================================================================
八、战斗／遭遇记录界面
======================================================================

1. 页面目标

参考包将战斗表现为“固定资源摘要＋敌对威胁块＋按回合累积的文字日志＋底部行动栏”。项目必须继承这一结构，但将战斗的重点放在敌方意图、环境、知识、准备和多种解决方式，而不是单纯伤害输出。

2. 页面结构

顶部栏：返回、标题“遭遇”或当前地点名、设置。
黏性状态区：玩家姓名、资源三列、敌方威胁块。
滚动战斗记录：回合／节拍分隔、我方行动、敌方行动、环境变化、状态结果、下一意图。
底部操作栏：攻击、观察／准备、物件／仪式、交涉、撤退等；根据宽度可分两行，不能小于44×44 CSS px。

3. 玩家资源摘要

参考包三列资源条的组织方式保留，项目语义改为：

生息：当前／上限，朱砂填充。
精力：当前／上限，焦金填充。
定力：当前／上限，冷月蓝或灰蓝填充。

资源条为1.5—2 px的细方形进度，不使用圆头、不使用高光渐变。数字永远可见。

4. 敌方威胁块

位于资源区下方，以低层表面、朱砂边框、警告符号、敌方名和细生命／稳定度条组成。敌方名称必须是《黑雨》内容，例如“含晦”，不能沿用“青丘九尾”。

敌方意图置于威胁块下方或最新日志末尾：认知不足时为行为描述；认知提升后显示更准确的下一节拍风险和可利用弱点。

5. 战斗日志

每个节拍以“第X节拍”居中弱标签开头。叙事动作使用完整句子，已知行动技能或物件以方括号内嵌强调，例如[囚雨芦]、[观察]、[封存]。伤害、状态、成功或失败使用单独一行强调文字，但不得压过上下文。

环境变化必须独立写入日志：黑雨、水位、白昼盐池、井壁、鼓声、旁观者等影响下一步可用行动。日志应说明状态来源和解除／应对方式。

6. 底部行动栏

参考包有“攻击／术法／撤退”三项等宽方形按钮。项目扩展为多解法，但保持方形细边、图标在上、标签在下、激活时旧丝填充反色的视觉：

第一排：攻击、观察、物件。
第二排或展开菜单：防御、移动、同伴、交涉、仪式、撤退。

若当前遭遇支持少量行动，可只显示当前可用项。撤退始终应在条件允许时可达，不得被藏在多层菜单中。

7. 操作逻辑

（1）点选行动后先进入目标／物件／说明选择，再确认执行。
（2）重复点击同一行动不得重复结算。
（3）战斗结算写入历史日志和事件记录，结果影响物品、人物关系、山海志和世界状态。
（4）退出／撤退应明确说明当前可能代价，但不泄露全部未来剧情。
（5）减弱动效模式关闭日志逐字和定位脉冲，保留行动结果。

======================================================================
九、角色／任务侧抽屉
======================================================================

1. 页面结构

顶部：关闭按钮。
角色块：圆形或切角头像、姓名、出身／身份、年龄或阶段、当前地点。
资源摘要：生息、精力、定力，可进入角色详情。
主入口：人物、事件／任务、行囊、阅读设置等。
行囊速览：4列方形格子，显示少量关键物品或快捷入口。
当前任务：主线与支线卡片，显示问题、摘要和细进度线。

2. 视觉细节

（1）抽屉背景使用标准表面色，不使用纯黑。
（2）角色块下方以淡金刷痕线分隔。
（3）当前主入口使用左侧2 px旧丝实线＋微弱底色，不使用大面积高亮。
（4）行囊格为方形细边框；空槽维持低对比，不显示假奖励。
（5）任务卡标签“主线／支线”嵌在卡片顶部边线上，如古籍签条。
（6）任务进度仅在可量化且不破坏叙事时显示；否则显示“正在追查”“等待回应”等文本阶段。

3. 项目内容映射

角色信息：姓名、出身、天性、缺陷、年龄、地点。
人物入口：关系档案、重要NPC、势力。
事件入口：主线、支线、奇遇与近期回响。
行囊速览：扶桑烬、裂陶哨、囚雨芦、骨牌等已持有关键对象。
禁止字段：修为等级、灵石货币、灵兽养成、门派入口，除非未来有批准需求。

======================================================================
十、山海志、人物与行囊的档案结构
======================================================================

1. 统一三级结构

类别切换／下拉选择 → 子项列表 → 点击详情卡。

参考包的侧抽屉格子和资料卡提供的是“摘要—进入—详情”的形式。项目档案页面必须继承此层级，不能把所有条目和全部长文同时铺在同一屏幕。

2. 山海志

类别：异象、人物、器物、材料、异兽、地理。
列表项：标题、当前来源声音、已解锁层数、弱状态图标。
详情：标题、类别、来源声音、可靠性、正文、矛盾版本、认知层级轨迹、关联物品／人物／地点。

3. 人物

类别：按势力或地区。
列表项：姓名、身份、当前地点、当前状态。
详情：人物目标、已知秘密、关系轴、近期变化、相关事件、山海志链接。

4. 行囊

类别：装备、行旅、材料、工具、线索、异物。
列表项：当前认知名称、数量、耐久／唯一性、类别。
详情：感官描述、来源、效果、代价、不生效原因、认知层级、关联山海志。

5. 详情卡视觉

使用参考包的深色资料卡：方形、1 px淡金边、顶部居中小符号、标题与右侧方括号类别、正文、细分隔。手机端以全宽底部卡或独立详情页呈现；桌面端可在右侧固定详情栏呈现。

======================================================================

1. AppTopBar

属性：title、leftAction、rightAction、sticky、safeArea。
状态：默认、滚动后、返回模式、菜单模式、加载、禁用。

2. BrushDivider

1 px，两端透明，中部淡金；可带中部菱形、残日或分类小图标。用于剧情节拍、抽屉分区、卡片标题和回合分隔。

3. NarrativeBlock

属性：timeLabel、locationLabel、text、isLatest、typewriterState。
类型：旁白、观察、系统记录、异兆、NPC对话、玩家说话、玩家行动。

4. ArchiveEvidenceCard

状态：未知、传闻、实证、洞彻、锁定、已获得、已失去。

6. StatusMeter

属性：label、value、max、tone、warningState。
样式：细方形轨道、固色填充、数字可见。

7. ThreatPanel

======================================================================
十二、交互、状态与可访问性
======================================================================

1. 统一操作原则

所有表现层操作映射为统一的业务命令；UI只负责显示和输入映射，不直接修改背包、关系、世界变量或存档。鼠标、键盘和触摸应触发同一个操作语义。

2. 触摸

最小触摸面积44×44 CSS px。相邻控件间距至少8 CSS px。地图拖动与地点点击要区分移动阈值，避免拖动结束误开地点。侧抽屉、底部卡和模态均支持合理的触摸关闭方式，但不依赖滑动作为唯一关闭方法。

3. 键盘

Tab顺序遵循视觉顺序；焦点使用2 px旧丝或朱砂轮廓、3 px偏移。地图缩放和定位有可聚焦按钮。抽屉和模态打开时管理焦点，关闭后回到触发元素。主流程不出现焦点陷阱。

4. 读屏语义

（1）顶部栏、主导航、抽屉、日志、回合、资源、地图和行动栏使用语义区域标签。
（2）NPC对话播报“某某，对话”；玩家记录播报“你，说话／行动”；异兆和系统记录播报其类别。
（3）逐字播放期间，“显示全文”可见且可访问；禁用选择应读出“剧情正在展开，请使用显示全文或等待”。
（4）状态条除了视觉长度，还要有当前值／最大值文本。
（5）地图地点名称和可达状态可被读出。

5. 高对比与减弱动效

高对比：正文、边框、聚焦和图标满足WCAG 2.2 AA；关闭／降低纸张纹理。
减弱动效：关闭定位脉冲、平滑抽屉、地图标记缩放、战斗文字动画和剧情逐字播放；直接显示完整文本和可操作选项。

6. 错误与空状态

保持参考包的低噪声表达：错误使用朱砂边线、明确文字和可恢复操作；空状态使用淡金符号、简短解释和下一步。不得只显示抽象错误码，不得用大面积红色遮罩覆盖主阅读。

======================================================================
十三、响应式与桌面扩展
======================================================================

1. 手机优先

360—720 CSS px：顶部栏＋单列主内容＋底部主导航；侧抽屉为覆盖层；档案详情使用底部卡或二级页。

2. 平板

721—1050 CSS px：可保留顶部栏和中央阅读列；角色抽屉可变为左侧窄栏；地图地点卡可变宽；档案页可实现“类别＋列表／详情”双栏。

3. 桌面

>1050 CSS px：保持当前三栏信息架构。中间是连续卷册阅读列，左栏为角色状态，右栏为导航和世界异兆。参考包侧抽屉的内容可在桌面转为左栏，但摘要、任务卡和行囊速览的信息顺序不变。

4. 不可变化的规则

（1）正文阅读列不因桌面变宽而无限拉伸。
（2）主要操作仍位于内容语境附近；不得把剧情选择移到远处侧栏。
（3）手机底部导航与桌面侧栏是同一导航模型的不同表现。
（4）档案三级结构和剧情历史回看在各断点保持一致。

（7）阅读设置与高对比模式。
