## 1. 目的、边界与真源优先级

本规范将意向图中有效的视觉语言转为可实现、可验收的规则。它服务于“发现异常 → 求证 → 准备 → 行动 → 后果 → 记录”的叙事闭环，不以复刻截图为目标。

真源冲突时按下列优先级执行：

1. 当前用户指示、产品说明书 V1.4、已接入内容包，决定玩法、数据、人物、世界事实与五项主导航名称；
2. 本 V1.4，决定视觉层级、页面版式、组件组合、状态表达和响应式规则；
3. UI V1.3，决定本文件未重新定义的精确令牌、触控、无障碍和平台迁移约束；
4. `02_视觉与交互/00 ui设计意向/意向图/`，只提供构图、材质、密度和信息组织参考，不可直接复制角色、地图、图标、文字、素材或数值；
5. 任何未批准的外部参考，均不得作为发布资源或玩法依据。

用户提供的 Figma 下载源文件 `02_视觉与交互/Figma导入包/2026-08-25 【下载】figma下载ui/` 属于本次预览的受控输入，但不自动等同于发布授权。只有已提取至 `Figma导入包/2026-08-25_UI视觉交互系统_V1.0/assets/figma-source-v1/`、并登记来源和用途的图像可以作为低层氛围素材使用；角色、物件、敌兽、选择缩略图和带有固有地点／剧情语义的素材仍需完成内容映射与授权确认后再接入。

### 1.1 本次纳入范围与功能边界

- V1.4 明确纳入遭遇战、装备、物品栏及其状态的视觉组件；它们应有与行游、命录、行囊一致的信息层级，而不是被藏入二级界面。
- 允许使用威胁名称、敌方意图、环境压力、生命/准备/认知资源条、行动栏、装备位、物件数量、当前装备、类别、稀有度和锁定/可用状态，前提是对应数据已存在或在后续数据规格中明确登记。
- 本规范不定义伤害公式、掉落概率、货币、装备强化、随机刷取、战力门槛或养成循环；无真实数据时只能使用“未记录”“待确认”等空状态，不能伪造数值。
- 不将意向图中的示例敌兽、角色名称、战斗数值、货币、头像、场景图、物品图、地图底图或 UI 图标裁切、导入或再发布。
- 不以“大金框、满屏纹样、纯黑、霓虹、高饱和渐变、玻璃拟态、大圆角卡片”制造所谓古风感。

## 3. 视觉总纲

### 3.1 五项不可违背原则

1. **湿墨为阅读底，旧丝为操作焦点。** 画布与容器保持暗、暖、低饱和；焦金只用于当前页、可操作入口、进度和关键边线。
2. **叙事节拍先于卡片堆叠。** 旁白以留白和刷痕分隔；卡片只承载物证、当前选择、地点、命轨等需要边界的对象。
3. **状态必须可被说出来。** 苔绿、朱砂、冷月蓝等语义色必须同时配合文字、图标或结构变化，不能只靠颜色传意。
4. **古意不牺牲可读性。** 小篆只用于游戏名、页面大标题、底部主导航；正文、数值、状态、错误与唯一操作识别使用高可读中文字体。
5. **画面不承诺未实现的系统。** 同一视觉元素只能读取已裁决的内容状态；“已接收”“已写入”“已回收”“未达成”必须分开表达。

### 3.2 反向原则

- 不用大面积金色、厚阴影或花哨边框制造层级；层级由表面深浅、1 px 细线与留白建立。
- 不将所有资料、关系、路线、风险与长选项压在同一叙事画面；完整账册应按需进入命录、行囊、志异或舆图。
- 不把未知、锁定或未验证内容画成“可领取奖励”。
- 不为引用意向图而伪造手机状态栏、商品化头像、现成风景或数值系统。

## 4. 设计令牌与使用规则

### 4.1 色彩：沿用 V1.3 精确值

| 语义 | 值 | 使用 |
| --- | --- | --- |
| 画布／湿墨石 | `#17130F` | 全局背景；不使用纯黑。 |
| 最深容器 | `#110E0A` | 嵌入面、遮罩内层、深阅读底。 |
| 低层／标准／高层容器 | `#1F1B17` / `#231F1B` / `#2E2925` | 对话、资料卡、抽屉和被选中内容的层级。 |
| 最高层容器 | `#39342F` | 模态、强选中或高对比的受限使用。 |
| 主／次／弱文字 | `#EAE1DA` / `#CEC5B9` / `#979085` | 正文、辅助说明、禁用/次要说明。 |
| 弱边框 | `#4C463D` | 普通容器和网格；不得单独承担状态。 |
| 旧丝／主要填充 | `#FFF2DE` / `#E6D5B8` | 当前页、主要操作文字及按下态。 |
| 焦金／进度金 | `#F5D294` / `#D5C5A8` | 标题局部、当前边线、进度、刷痕中心；常规边线约 30% 透明度，聚焦提升到约 60%。 |
| 朱砂／危险文本 | `#920703` / `#FFB4AB` | 不可逆、敌对、伤势、关键危险；须附 `[危]`、危险说明或图标。 |
| 冷月蓝／苔绿 | `#6E8298` / `#6F8A78` | 认知、地点、可采集、已写入或当前路径；须有文字。 |

### 4.2 字体与字阶

- 显示标题：36 px / 700 / 1.2 / 0.1em；大标题：24 px / 600 / 1.4；手机标题：20 px / 600 / 1.4。
- 叙事正文：18 px / 400 / 1.8；窄屏逻辑下限为 16 px，不能为塞入内容继续缩小。
- 辅助正文：14 px / 400 / 1.6；标签与系统信息：12 px / 700 / 1 / 0.2em。
- 标题优先 Noto Serif SC／思源宋体；正文优先 Literata 或高可读中文宋体；标签可用 Source Serif 4／思源黑体。字体资源未获授权或未随包时必须回退，不依赖在线 CDN。

### 4.3 间距、形状与纹理

- 只使用 `4 / 8 / 12 / 16 / 20 / 24` CSS px 间距阶。页面边距 20，最窄 360 CSS px 时不低于 16；叙事大段落至少 24。
- 所有常规容器、标签、行动卡、地图浮层与抽屉均为直角；如为运行时兼容保留圆角，最大 4 px。
- 1 px 细金边取代厚阴影；分隔线为两端透明、中部淡金的刷痕线，可在中心放小菱形或分类符号。
- 5% 细颗粒纹理只作低对比底层装饰，永不拦截交互、永不降低正文对比。地图可使用弱 50 px 网格，遭遇区可使用弱点阵。

## 5. 全局框架

### 5.1 顶部栏与情境条

- 顶部栏高度 64 CSS px，外加安全区；三列结构为左侧菜单/返回、中间视觉居中标题、右侧人物/设置/页面工具。左右控件宽度不同也不得挤偏标题。
- 手机布局必须把顶部安全区作为独立占位，不得让标题、返回、更多或情境条进入状态栏／灵动岛区域；当前模拟器基线为 iPhone 15 顶部 59 CSS px，iPhone SE 20 CSS px，Android 标准 24 CSS px。安全区只提供布局空间与可视化边界，不伪造真实系统图标。
- 常规功能页在顶部栏使用当前页标题；沉浸式行游可使用“山海异闻录”作为标题，情境信息放入其下方的独立条，不把品牌、章节、地点、天气都塞进同一行。
- 行游专属情境条顺序固定为：地点 → 时段/天气 → 当前不可错过的压力。它不是全局资源栏，离开行游即隐藏。

### 5.2 底部五项主导航

固定顺序为：**志异／命录／行游／行囊／舆图**。五项等宽分布，图标在上、文字在下，每项最小触控面积 44×44 CSS px，固定栏高 60–64 CSS px并预留底部安全区。

- 当前项使用亮旧丝图标、较亮文字和上缘或左缘细线共同表达；非当前项使用弱文字。
- 图标与短标签必须同时保留，宽度不足时可压缩标签但不得仅留图标。
- 行游是叙事主入口，位置居中不表示“更高战力”或“首页奖励”。

### 5.3 内容层与响应式

- 手机 360–720：顶部栏 + 单列内容 + 底部五导航；正文、选择、地图地点卡互不遮挡。
- 平板 721–1050：保留同一导航模型；档案可“类别 + 列表/详情”双栏，舆图与地点卡可并排。
- 桌面 >1050：连续阅读列宽最大约 672 px；左右可展开角色摘要、导航或异兆辅助栏，但剧情选择始终邻近正文。
- 侧抽屉最大 320 CSS px 且不超过视口 80vw；同一时刻不与第二个模态框叠开。

## 7. 五个主页面的可执行版式

### 7.1 行游：当前叙事与选择

阅读顺序：情境条 → 旁白 → NPC 对话 → 玩家已选记录 → 异兆/观察 → 物证卡 → 待做选择 → 回到最新/人物快捷入口。

- 剧情手机页按意向图拆为八个连续层级：状态栏安全区、品牌快捷区、地点／章节／天气情境条、场景主视觉、角色对话卡、异兆记录卡、三项选择卡、人物／收起操作与底部五项导航。品牌快捷区只放命录、舆图、行囊和更多入口，不承载剧情正文。
- 对话卡统一采用“头像首字占位 + 角色名 + 正文”结构；主角、NPC、异兆分别使用独立的语义类名和边框层级。异兆记录必须有独立图标、标题和说明，不能伪装成普通 NPC 发言。
- 对话采用左右栏：NPC 卡片靠左，左边缘使用加粗焦金竖线；玩家卡片靠右，右边缘使用加粗焦金竖线，头像与文本镜像排列。人名恒为焦金色，对话正文恒为旧丝白色；旁白不使用对话框，独立以全宽文字插入对话节拍。
- 异兆不使用角色头像、对话框或原型图标；剧情流内以无边框“系统提示”文字出现，点击后再打开独立的异兆详情弹窗卡片。弹窗只呈现已经记录的事实，不提前暴露剧情结果。
- 已登记的 Figma 下载源头像可替换角色首字占位；头像始终是表现层，角色名、当前关系和对白仍从剧情数据读取。选择卡可使用已登记缩略图，但行动标题、状态标签、风险和后果不得从图像推断。
- 场景主视觉是叙事氛围层，不承载关键文本；正式资源未登记前使用几何／渐变占位，避免把意向图中的角色、场景和图标资产直接带入工程。
- 选择区固定提供 2–3 个行动；以 390 CSS px 参考画板时单项约 96 CSS px，组件顺序为“72 CSS px 缩略占位 + 行动标题／风险、关系或代价标签 + 简短说明 + 箭头”。窄屏按比例收缩并保持可读触控面积；正式缩略资源未登记前使用几何／渐变占位。预览允许点击选中并反馈，但不在视觉原型中写入剧情数值或存档。

- 每个节点以刷痕线和“最新剧情”标识开始；进入节点只自动定位一次，玩家上翻后不被持续强制滚动。
- 对话头像仅在具有原创且获授权的头像时显示；否则使用人物首字或符号占位，不能让头像压过正文。
- 选择卡上方可使用一句短提示，如“此刻的行动会留下痕迹”；每项显示行动动词、类型（说话/行动/观察/准备）、已知来源或锁定条件。
- 逐字播放时选择不可用并提供“显示全文”；减弱动效下直接显示全文及选择。双击/快捷操作的具体行为仍由现有产品交互基线决定。

### 7.2 命录：故交、命轨、余响

- 二级标签为“故交／命轨／余响”，默认显示与当前叙事最相关的层级；不再使用“总览、主线、支线、结局、回溯”的泛化标签直接替代产品信息架构。
- 命轨画布先显示主干与当前节点，分支按需展开；实线、虚线、锁标记、状态文字共同表达完成、可回访和未达成。
- 节点详情固定回答五件事：此节点是什么、玩家已做何选择、即时结果、已知后续读取方向、关联的人/物/地点。不能展示隐藏变量名或未解锁剧情。
- 余响只列出已偏离初态、且有明确回收位置的记录；用“已写入”“本卷回读”“下卷读取”这类非剧透文案。

### 7.3 行囊：随身物与在身装备

- 顶部先分“随身物／装备”，再显示类别；推荐类别为装备、行旅、材料、工具、线索、异物，项目已有合并规则时以内容包为准。
- 条目为方形格或纵向列表，不得同时在首屏铺开全部长说明。选中后在底部详情卡或二级页展示感官描述、来源、当前用途、代价/不生效原因、认知层与关联志异。
- 数量、唯一性、已装备状态必须可读；物件图片缺失时使用命名/分类符号占位。
- 装备页优先表现“人物当前携带了什么、这件物品正在影响什么”。可使用人物剪影/立绘作为中心锚点，七个在身装备位环绕或分列；下方展示由真实数据提供的属性摘要、状态变化或套装/关联提示。数据缺失时显示空位与说明，不能伪造战力或强化数值。

### 7.4 舆图：被记录过的世界

- 地图画布占顶部栏与地点卡/底部导航之间的主要区域，可拖动、缩放、回中；拖动结束不得误触地点。
- 地底图是低饱和地貌与弱网格，不把地点名烘焙在图片里。标记是独立语义层，名称、状态与可达性可由读屏读取。
- 地点卡顺序：名称 → 类型符号 → 刷痕线 → 2–3 行环境描述 → 方括号状态 → 可执行动作。地图资源缺失时保留地点列表作为降级路径。
- 当前点采用实心定位 + 静态淡金环；减弱动效时关闭脉冲而不隐藏当前位置。

### 7.5 志异：已得见闻的档案

- 维持“类别 → 条目列表 → 详情卡”三级结构。类别推荐异象、人物、地理、异兽、器物、材料、文书，具体可见项由内容解锁决定。
- 列表项显示标题、来源/初见位置、当前知识层和弱状态符号；详情按“初见、传闻、行证、推论、余响”组织，不将后续层预先露出。
- 锁定、传闻、实证、洞彻、已失去等状态必须配合方括号文字或符号，不以颜色独立区分。
- 神兽分类使用三列竖向收集卡：插画／名称／已收集或未收集状态。点击已收集卡打开可关闭的欣赏详情层；详情仅展示已确认的分类、传闻、奖励和关联项，未收集卡不得补造图鉴内容。

### 7.6 命录与系统入口

- 命录的主线页使用中心主轴加左右分支的导图结构：主线为实线、已写入路径可用苔绿光线、未选择／锁定分支为虚线，并配合文字与锁定符号说明状态。节点详情置于导图之后，不遮挡导图本身。
- 页面左上角返回按本次会话内页面历史回退；无历史时返回主页。右上角只保留“···”设置入口，不与主导航重复堆叠快捷图标。
- 用户明确要求直用 Figma 下载整页源稿时，可在**视觉预览包**中以 SVG 作为底图并叠加独立透明语义热区；不得将烘焙在 SVG 中的文字、地点或物品当作运行时数据。正式 Web／小游戏必须以原生组件、可读文本层与按需压缩资源替代。

### 7.7 主页与遭遇战预览

- 主页采用全屏、已登记的原创或获授权氛围背景；标题置于上方留白，左右为设置／公告／云存档／账号／客服入口，中下部依次为新建角色、选择角色、角色存档位和更多存档。未接入账号或云存档时必须明确为预览，不得模拟已上传或已登录状态。
- 遭遇战的信息顺序固定为：敌方名称与红色生命／怒气 → 战场意象与行动序列 → 我方或队伍蓝色体力／灵力与怒气 → 战斗记录 → 固定行动栏。行动栏默认可使用攻击、术法、防御、物件、撤退；每项动作须有文字，红蓝颜色只作阵营辅助。
- 正式战斗数值、队伍组成、伤害公式、法术消耗和撤退规则必须由已批准战斗数据提供。预览可显示交互示例，但须标注不写入剧情、队伍或存档。
- 在正式战斗数据批准前，遭遇预览采用有限白盒流程：**剧情预兆 → 迎战／尝试撤离 → 动作反馈 → 预览胜利／失败或撤离 → 剧情余响**。流程未达到三种结算之一时，返回与主导航不得绕过遭遇；撤离不生成战利品、奖励或存档写入。红蓝仅表达敌我阵线，界面改用意图、行动状态和文字反馈，不能伪造生命、怒气、伤害、概率或掉落。

## 8. 遭遇、装备与物品栏的可视化强化

### 8.1 遭遇战界面

- 当剧情进入遭遇态时，顶部栏下依次为：当前地点/天气 → 敌方威胁块 → 玩家资源摘要 → 回合/事件日志 → 固定行动栏。威胁块可包含名称、类型、意图、已知弱点、危险等级与状态。
- 行游剧情中可展示一个明确标注的“遭遇预兆”入口进入遭遇页。遭遇页可播放敌方意象的入场、待机和行动反馈动效；动效只服务于读秒与反馈，不得伪造回合结果、敌方弱点或数值，且必须受 `prefers-reduced-motion` 降级约束。
- 敌方必须有轮廓锚点：获授权的插画、剪影、符号或文字占位均可。即使没有图像，名称、意图与危险原因仍须完整可读。
- 玩家资源条显示名称、当前值/最大值、状态说明，且每条使用不同的语义色与图标；高危险除朱砂外还须有 `[危]` 或明确文字。
- 行动栏优先使用观察、准备、物件、交涉、撤退；若内容数据提供攻击、术法、仪式等行动，可按同一组件插入，不能因视觉需要自行添加。
- 每次行动的反馈顺序为“已接收 → 执行中/受阻 → 结果 → 下一意图”；减弱动效下保留完整日志与即时结果。

### 8.2 装备与属性界面

- 中心使用人物剪影/立绘或不遮挡文字的象征图；装备位分左右或环绕排布，包含武器、头部、衣甲、护腕、戒指/信物、腰带、鞋履、项链等已定义位置。具体位数与名称以内容/数据规格为准。
- 单个装备位固定显示：位置名称 → 物件缩略图/占位 → 当前认知名 → 装备状态 → 已知变化。变化可为属性、能力、地点行动、关系或剧情条件，不限于战斗。
- 属性摘要采用两列或三列短行，按“名称 + 当前值/描述 + 来源”组织；套装/关联效果只在真实数据存在时展示，并标明已激活数量或未满足条件。
- 页面底部的操作应为“查看详情、替换、卸下、比较”等业务动作；强化、培养、锻造等动作只有在后续产品明确批准并完成数据契约后才显示。
- 装备位或物件缩略图点击后可打开详情卡。卡片顺序为：装备位／名称 → 图片 → 当前已知详情 → 丢弃／使用／给予或交付。丢弃必须在正式版提供二次确认；使用、给予和交付必须由真实物品效果、目标和任务条件决定，预览阶段不得直接修改存档。

### 8.3 物品栏可见性

- 行囊网格在手机端优先 4 列方格；屏宽不足时最小缩至 3 列，不通过缩小文字或触控面积硬塞 5 列。格内包含缩略图/占位、数量或唯一标记、稀有度/状态小角标和当前选中边线。
- 选中物件以焦金细边 + 详情卡的双重变化表达；已装备、任务物、可使用、锁定、未知等状态均有方括号标签或图标辅助。
- 分类、排序、容量和筛选必须在列表顶部可见，但不盖过物件网格；详情卡只显示当前已知名称、描述、来源、用途、代价和关联入口。
- 交互预览中的物品格、选中态、详情与操作必须为独立语义组件，并在主内容滚动区为固定底部导航预留空间；不允许以烘焙文字的整页 SVG 充当行囊运行时详情层，避免详情失真、热区重叠或导航被遮挡。整页 SVG 可保留为 Figma 视觉底稿与归档来源。
- 图像未到位时，使用同尺寸的类别符号与名称占位，保证网格节奏、数量和状态仍可读。

## 9. 交互、动效与可访问性

- 所有触摸操作最小 44×44 CSS px，相邻控件至少 8 px；键盘焦点为 2 px 旧丝/朱砂轮廓并留 3 px 偏移。
- 游戏阅读视口与展示用模拟器采用无轨滚动：不显示右侧滚动条，但必须保留触摸上下滑动、鼠标滚轮和键盘阅读。编辑器、长表单和设计工具面板可保留独立滚动，不能因此导致属性无法访问。
- 故事选择卡、缩略图和状态标签沿用直角描边规则；可点击卡片与固定导航在按下时给出轻微下压反馈，减弱动效环境下仅保留即时状态变化。
- Tab 顺序与视觉顺序一致；侧抽屉和模态关闭后焦点返回触发控件；地图缩放、回中与地点卡必须可聚焦。
- 点击反馈顺序为：输入已接收 → 状态成功/受阻 → 结果分级 → 页面/状态转场。未写入前不能使用“完成”视觉。
- 视觉预览可提供独立的“调整模式”，用于验证标题、文字大小、版面密度、安全区、色彩令牌及辅助网格；此模式与游戏设置、剧情、战斗和存档数据隔离，允许恢复默认和导出仅含视觉参数的配置。物件详情若以模态信息卡呈现，必须只在点击明确物件后打开，并支持点击卡外遮罩或关闭控件退出。
- Figma 交付必须同时提供：可编辑的 `Screen/` SVG 画板、`Component/` 母版命名、组件/变体/原型/动效映射，以及同版本交互预览。SVG 导入仅保证矢量组、文本和命名可编辑，不得声称会自动生成 Figma 原生组件、原型连线或时间轴；需要原生对象时，须在指定 Figma 文件内按映射创建。
- 面向设计迭代的网页画板编辑器应作为独立表现层模块接入：编辑态与试玩态互斥；移动、缩放、图层排序、组合、组件标记、隐藏、对齐、网格/参考线只改变可导出的视觉布局稿，不直接删除业务节点、改写剧情/存档或劫持正常交互。跨应用复用时以宿主画板根节点、工具栏、图层容器与存储键为接入边界。
- 编辑器必须提供固定可见的“保存布局／取消本次编辑”操作：保存将当前视觉布局作为本次会话基准；取消恢复至进入编辑器或上次保存时的布局。页面与图层面板须独立呈现、可拖动，并以页面→容器→最小可选图元的父子树展示名称、类型、位置、缩放、组件、关联分组和动效标记。基础游戏页面只读保护；设计师新增的编辑页面与图元可移除。拖拽在 Shift 按住时锁定首次判定的水平或垂直方向，并继续保留网格、中心及同级边缘的吸附提示。
- 编辑器工具条必须支持撤销／重做（按钮与 Ctrl/⌘+Z、Ctrl/⌘+Shift+Z／Ctrl/⌘+Y），且撤销范围至少覆盖移动、缩放、旋转、可编辑文字和图层属性。选框以选中图元的实际渲染边界为准，不以父容器伪元素扩张。属性面板至少提供命名、关联标识、精确 X/Y、精确缩放／旋转、动效、组件与锁定；文本、符号图标和图片分别通过可编辑内容、符号输入和素材替换完成。编辑态必须阻断宿主试玩按钮，以选择而非触发业务动作。
- 对齐操作在单选时以画板边界为参考，在多选时以选区边界为参考；选中、移动、缩放、对齐时展示与最近可选图元的水平距离、垂直距离和本体宽高。隐藏与删除不得合并为同一个动作：隐藏可恢复，删除明确标示为移除图元。图层树行支持拖拽调整逻辑父级／同级顺序，右键菜单至少提供复制、隐藏、置顶和组件标记。属性面板同时支持透明度、倒角、边框粗细及边框颜色。
- 高对比模式提升正文、边线、焦点和图标对比并降低纹理；减弱动效关闭地图脉冲、视差、平滑抽屉和逐字效果，但保留所有信息。
- 错误使用朱砂边线 + 明确文字 + 可恢复操作；空状态使用淡金符号 + 简短说明 + 下一步，不使用抽象错误码或满屏红色遮罩。
