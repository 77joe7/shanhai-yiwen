# Web 与移动浏览器适配规范

## 1. 适用目标

当前版本应首先在桌面浏览器和手机浏览器中完成预览与验收，同时避免阻断后续微信小游戏适配。

在技术栈与目标用户设备数据尚未确定前，最低验证基线为：

- 桌面端：当前稳定版及前一个主版本的 Chrome、Edge；
- Android：系统 WebView/Chrome 的当前稳定版及一台中低端真实设备；
- iOS：当前主要版本及前一个主要版本的 Safari，至少一台真实设备；
- 视口：常见窄屏手机、全面屏手机、平板/折叠屏边界和桌面宽屏；
- 输入：鼠标、键盘（适用时）、单点触控和多点触控（适用时）。

正式发布前应根据目标用户、分析数据和平台政策批准精确支持矩阵，不应无限承诺所有浏览器。

## 2. 布局与显示

- 采用响应式布局或统一逻辑画布缩放方案，不以单一设计稿尺寸作为运行假设。
- 明确游戏支持横屏、竖屏或两者；不支持的方向应给出清晰提示，并保持存档与状态安全。
- 使用安全区域信息处理刘海、挖孔、圆角、状态栏、底部手势区和浏览器工具栏。
- 核心按钮、文本、资源和提示不得被裁切或置于难以触达区域。
- 画布尺寸、CSS 尺寸和设备像素比应分离处理；窗口变化后重新计算，避免模糊、拉伸和坐标偏移。
- 文本应允许本地化后的长度变化，不将关键文本烘焙进图片。

## 3. 输入与交互

- 业务动作映射为统一输入命令，表现层负责将鼠标、键盘和触摸转换为命令。
- 可交互控件应具有足够触摸面积和间距，不依赖悬停表达唯一信息。
- 处理 `pointerdown`、移动、取消和释放的完整生命周期，防止滑出、切后台或系统手势导致卡住状态。
- 对双击缩放、页面滚动、长按菜单、下拉刷新和浏览器返回行为做明确策略，禁止粗暴全局屏蔽影响可访问性。
- 防止一次触控同时触发触摸与合成鼠标事件；奖励、购买和提交类操作应防重复执行。
- 提供可见焦点、合理对比度和可辨识状态；关键流程不只依赖颜色、声音或复杂手势。

## 4. 生命周期与恢复

- 统一处理页面可见性、窗口失焦、冻结/恢复、页面销毁和移动设备前后台切换。
- 进入后台时暂停需要暂停的计时、动画和音频，保存必要状态并停止非必要请求。
- 回到前台时根据真实经过时间恢复，禁止无条件补算导致奖励、战斗或冷却异常。
- 页面刷新、崩溃或被系统回收后，应能从最近有效存档恢复；关键写入避免只依赖卸载事件。
- 网络从离线恢复时应重新验证会话与服务器状态，避免盲目重放非幂等请求。

## 5. 音频与媒体

- 适配移动浏览器的用户手势解锁规则；首次有效交互后再初始化或恢复音频。
- 提供音乐、音效和总音量控制，并持久化用户选择。
- 前后台切换、耳机/音频焦点变化时按设计暂停或降低音量，不得重复叠播。
- 音频格式、并发数、解码内存和首包体积纳入资源预算；准备兼容格式或回退方案。

## 6. 网络、缓存与存储

- 网络请求统一封装超时、取消、错误分类、有限重试和可观测信息。
- 只对安全或幂等操作自动重试；奖励领取、购买和状态提交必须使用幂等标识或服务端去重。
- 清楚区分静态资源缓存、运行时缓存和玩家数据，不因清缓存破坏远端权威数据。
- 浏览器存储容量、隐私模式和系统清理均不可靠；写入失败必须可感知并提供降级或提示。
- 更新版本时使用内容哈希或版本清单避免新旧资源混用；Service Worker 若启用，必须设计更新与回退流程。
- 所有生产网络通信使用 HTTPS；跨域、内容安全策略和资源来源采用最小许可。

## 7. 性能预算与测量

项目确定引擎与首个可运行版本后，必须用 ADR 或发布计划填写以下预算：

| 指标 | 桌面 Web | 移动 Web | 测量条件 |
| --- | --- | --- | --- |
| 首次可见时间 | 待基准测试 | 待基准测试 | 冷缓存、受控网络 |
| 可交互时间 | 待基准测试 | 待基准测试 | 冷缓存、生产构建 |
| 稳态帧率/帧时间 | 待基准测试 | 待基准测试 | 真实玩法场景 |
| 峰值内存 | 待基准测试 | 待基准测试 | 目标设备 |
| 首包/初始下载量 | 待基准测试 | 待基准测试 | 压缩后传输量 |
| 单场景资源峰值 | 待基准测试 | 待基准测试 | 最重目标场景 |

未定量前仍应遵守：避免同步长任务、逐帧分配、无界对象增长、重复资源、超大纹理和一次性加载全部内容。性能报告应记录设备、系统、浏览器版本、构建版本、网络和测试场景。

## 8. 调试与发布验收

- 开发服务器与生产构建均需验证，不能以热更新开发环境代表发布结果。
- 检查控制台错误、未处理 Promise、404、资源跨域、混合内容和缓存版本错配。
- 每个发布候选至少验证：启动、核心玩法、触控、旋转/缩放、前后台、断网恢复、存档读写、音频解锁和更新缓存。
- 真机验证优先于仅使用桌面响应式模拟器；iOS Safari 和目标 Android 设备不可完全由模拟代替。
- 发现平台差异时先修复适配层，不在核心业务中堆叠设备判断。
