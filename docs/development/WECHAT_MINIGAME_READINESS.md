# 微信小游戏迁移准备规范

## 1. 目标

本规范用于确保当前 Web/移动 Web 实现可以在后期以受控成本迁移到微信小游戏。它不代表当前已经接入微信能力，也不替代接入时对最新版微信官方文档和平台政策的核验。

## 2. 平台抽象契约

业务层只依赖项目定义的接口，不直接调用浏览器或微信专有 API。至少预留：

- `StoragePort`：存档、设置、容量错误和迁移；
- `LifecyclePort`：启动、显示、隐藏、恢复和退出意图；
- `InputPort`：指针、触控、键盘与平台事件；
- `AudioPort`：解锁、播放、暂停、音量和前后台行为；
- `NetworkPort`：请求、超时、取消、重试和网络状态；
- `AssetPort`：主包、分包、远程资源、缓存和版本清单；
- `SafeAreaPort`：屏幕、方向、像素比和安全区域；
- `IdentityPort`：游客、本地身份与后续微信登录；
- `SharePort`、`AdPort`、`PaymentPort`：默认无能力实现，只有需求批准后启用。

Web 版和微信小游戏版应通过构建配置选择适配器，不应复制玩法代码形成两套分支。

## 3. 从第一阶段开始的约束

- 核心逻辑不得依赖 DOM 节点、CSS 布局、`window`/`document` 全局状态或浏览器事件对象。
- 禁止把 `localStorage`、IndexedDB、Cookie 或文件路径写入业务层。
- 禁止依赖 `eval`、`new Function`、运行时下载并执行代码或其他可能违反小游戏环境/政策的动态执行方案。
- Worker、WebAssembly、WebGL 特性、音视频接口和第三方 SDK 在采用前必须验证目标环境支持与包体影响。
- 资源路径和加载方式通过资源清单管理，处理大小写、主包/分包、远程下载、缓存失效和失败重试。
- 不假定页面始终存活；所有关键状态能够在隐藏、系统回收和重新进入后恢复。
- 不在客户端保存服务端密钥，不信任客户端对奖励、支付和排名的最终判定。

## 4. 包体与资源策略

- 从早期开始统计源代码、依赖、图片、音频、字体和首屏资源大小。
- 将启动必需内容与可延迟内容分离，为主包、分包和远程资源下载预留边界。
- 资源采用内容哈希或版本清单，缓存命中与清理必须可控。
- 大资源需要压缩、降级或按需加载方案；低内存时允许释放并重新加载非关键资源。
- 微信平台具体包体、分包和缓存限额可能变化，正式接入及每次发布前必须核对官方最新规则，不在本文件硬编码易失效数值。

## 5. 生命周期、存档与网络

- 将浏览器可见性与微信显示/隐藏事件映射到统一生命周期状态机。
- 隐藏时保存最小必要状态并暂停实时逻辑；恢复时使用可信时间源校正。
- 本地存档格式跨适配器一致，平台差异只存在于存储实现；云存档另设同步与冲突策略。
- 本地数据可能被清理或受容量限制；重要进度在业务批准后设计账号/云端恢复机制。
- 弱网和断网流程必须可用；登录失效、请求超时、重复回调和进入前后台时的请求竞争均需测试。

## 6. 平台能力接入门禁

登录、用户信息、分享、排行榜、广告、支付、订阅消息和数据分析等能力只有在满足以下条件后才能接入：

- 存在已批准的产品需求和交互方案；
- 核对接入时最新的微信官方 API、审核规范、隐私保护指引和适龄要求；
- 明确失败、拒绝授权、未成年人、重复回调和降级流程；
- 第三方 SDK 完成许可证、安全、包体和数据流审查；
- 隐私政策、用户授权和数据删除/导出机制符合实际收集行为；
- 真机与体验版完成验证，不只依赖开发者工具。

## 7. 迁移验收清单

进入微信小游戏适配阶段时至少验证：

- 生产构建可在当前微信开发者工具中导入且无阻断错误；
- 至少覆盖一台 iOS 和一台中低端 Android 微信真机；
- 首次启动、二次启动、分包/远程资源和缓存更新正常；
- 显示、隐藏、锁屏、来电、网络切换和内存压力后状态正确；
- 触控坐标、安全区、横竖屏、音频和字体显示正常；
- 本地存档、旧版本迁移、容量不足和损坏恢复正常；
- 登录及所有已启用的平台能力覆盖同意、拒绝、取消、超时和重复回调；
- 包体、内存、帧率、加载时间符合届时批准的预算；
- 隐私、内容、广告、支付和版本审核材料齐全；
- Web 版本核心玩法回归通过，确认平台适配没有分叉业务行为。
